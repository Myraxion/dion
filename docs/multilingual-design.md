# 多语言支持设计

状态：已实现；行为契约见 [spec.md](spec.md)。

## 目标与已确认范围

2026-10-10，用户确认首批支持简体中文和英文，覆盖程序生成的帮助、错误提示和列表错误汇总。

- 语言切换只影响程序文案。用户备注、文件名和备注文件内容保持原样。
- 命令名、选项名和 JSON 字段名保持现有英文写法。
- 增加英文 README，覆盖安装、命令用法和关键限制；内部规格、ADR 和开发文档继续使用中文。
- JSON 中供人阅读的 `message` 跟随所选语言。字段名、错误代码和退出码保持稳定；脚本根据 `code` 判断错误，需要英文文案时显式指定英文。

## 语言选择与错误边界

2026-10-10，用户确认：

- 增加 `--lang` 和 `DION_LANG`，优先级为命令行参数、环境变量、Windows 用户界面语言。
- 两个显式入口均未指定时跟随 Windows 用户界面语言；不支持的系统语言回退英文。
- 环境变量用于固定日常语言偏好，不新增配置文件。
- Dion 翻译自己的提示，保留底层系统错误原文、路径和错误编号。允许本地化上下文与系统原文混合。
- 外部编辑器的界面语言由编辑器自身控制。

## 语言值与回退

2026-10-10，用户确认：

- `--lang` 和 `DION_LANG` 接受 `en`、`zh-CN`、`auto`，值不区分大小写。
- `auto` 直接使用 Windows 用户界面语言。显式 `--lang auto` 覆盖 `DION_LANG`。
- 参数按独立值输入，例如 `--lang en`；不增加等号传值或紧连传值。
- 无效、缺值或重复的 `--lang` 报 `invalid_argument`，退出码为 2。
- 空或不支持的 `DION_LANG` 按未设置处理，继续检测 Windows 用户界面语言；有效命令行参数覆盖环境变量。
- 中国大陆和新加坡的简体中文用户界面映射为 `zh-CN`；繁体中文和其他未支持语言回退英文。检测失败也回退英文。
- 语言切换不改变名称匹配、排序及备注读写行为。

Windows 用户界面语言不同于区域格式语言。检测只使用当前用户界面语言，不遍历首选语言列表寻找后续支持语言。官方依据：[GetUserDefaultUILanguage](https://learn.microsoft.com/en-us/windows/win32/api/winnls/nf-winnls-getuserdefaultuilanguage)、[用户界面语言管理](https://learn.microsoft.com/en-us/windows/win32/intl/user-interface-language-management)。

## 全局选项与参数错误

2026-10-10，用户确认：

- `--lang` 是全局长选项，可放在命令前后；只增加这一入口，无短选项。
- 识别真正作为选项出现的第一个 `--lang`，其有效值控制本次调用的全部程序文案，包括发生在它之前的参数错误。
- 第一个语言选项无效或缺值时，使用环境变量、Windows 用户界面语言及英文回退规则选择诊断语言；后面的重复语言选项不改变诊断语言。
- 重复语言选项仍然报参数错误，不使用最后一个值覆盖前面的值。
- 识别语言选项时遵守参数值位置，不把 `--color`、`--comment-file/-f` 或 `--lang` 消耗的值重新识别为语言选项。
- 选项分隔符 `--` 后的所有参数仍作为路径或正文处理，不改变语言。
- 保持现有 JSON 选项、帮助、命令别名、输入来源互斥与列表模式互斥规则。帮助仍是文本，跟随所选语言，即使同时指定 `--json`。

| 调用 | 行为 |
| --- | --- |
| `dion --bad --lang zh-CN` | 中文参数错误 |
| `dion --lang en --lang zh-CN` | 英文提示重复选项，退出码 2 |
| `dion --lang fr` | 按环境变量或系统语言提示无效值，退出码 2 |
| `dion list --color --lang zh-CN` | `--lang` 是非法颜色值，不作为语言选项；按环境变量或系统语言提示参数错误 |
| `dion set file -- --lang` | 将 `--lang` 作为备注正文，不改变语言 |

## 资源交付与文档

2026-10-10，用户确认：

- 两种语言完整编译进单个 exe，不增加外部语言包或下载机制。
- 新增程序文案时同时维护中英文，首批交付要求两种语言覆盖完整。
- 英文使用文档为根目录的 `README.en.md`，与中文 `README.md` 互相链接。
- 首批实现保持轻量，围绕已确认的两种语言组织，不引入通用语言包系统或额外持久化设置。

## 实施方向

- 在集中模块中组织语言选择和中英文文案，保持备注解析、存储与名称比较的现有职责。
- 诊断保留可识别的错误种类和动态数据，在呈现边界生成所选语言的文本或 JSON `message`；不通过替换已生成字符串进行翻译。
- 翻译覆盖帮助、用法提示、参数校验、备注格式与编码诊断、文件操作上下文、列表汇总、物理行号提示及恢复文件提示。用户数据、路径和系统原文原样保留。
- 自动检测采用 `GetUserDefaultUILanguage()` 的简单调用，明确匹配简体中文标识，其他结果使用英文。简体 `zh-CN`、`zh-SG`、`zh-Hans` 及 Windows 的简体中性标识使用同一份简体文案；繁体标识不归入简体。标识对应关系见 [Microsoft 语言标识表](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-lcid/a9eac961-e77d-41a6-90a5-ce1a8b0cdb9c)。
- 测试中显式固定语言，避免已有中文断言和英文恢复路径断言依赖开发机设置；新增真实 CLI 双语验收。
- 实施时同步更新行为契约、相关设计文档中固定中文帮助的描述、文档导航和两份 README。实现完成前不把计划写成当前已实现行为。

## 验收范围

用户已确认双语覆盖帮助、参数错误、操作错误、列表错误汇总和编辑失败恢复提示，并验证语言优先级及用户数据原样保留。具体检查：

- 中英文总览、四个子命令及别名帮助等价；帮助不读取正文、不修改备注、不启动编辑器。
- `--lang` 覆盖 `DION_LANG`；`auto` 绕过环境变量；空或不支持的环境变量使用系统检测；简体、繁体、其他语言及检测失败符合回退规则。
- 有效语言控制早期参数错误，重复、缺值、无效值、值参数位置及 `--` 后字面文本符合上述约定。
- 文本和 JSON 的人读诊断跟随语言；字段、错误代码、退出码、路径及物理行号保持原契约。JSON 帮助仍是文本。
- 两种语言覆盖列表跳过错误、备注格式和编码错误、文件操作错误及编辑失败后的恢复提示。系统错误原文不要求与所选语言一致。
- 切换语言不改变备注正文、记录名称、成功 JSON 数据、文件字节、修改行为、名称匹配或列表排序。
- 英文 README 与中文 README 的命令、选项、默认行为和限制一致。
- 执行统一检查入口 `scripts/check.ps1`，确认格式、Clippy、完整测试和 Release 构建通过；检查单 exe 产物及既有不超过 5 MiB 的体积目标。

## 实施前事实

- Dion 是 Windows 10/11 x64 命令行工具，交付单个 exe。
- `src/help.rs` 的帮助和列表错误区标题为中文，多数自定义诊断为英文；部分诊断直接包含系统错误原文。
- 目前没有语言选项、语言检测、配置文件或本地化依赖。
- 现行行为契约要求帮助为中文；实施后需要同步更新该规则。
- JSON 错误代码、退出码及结构已有稳定契约，`message` 用于供人阅读。
- 备注名称匹配不依赖用户语言设置；语言支持不能改变现有备注读写规则。
