# Total Commander 双向互操作实测报告

本文档记录 Dion 与真实 Total Commander（TC）在 Windows 平台上的双向互操作验收结果，对应 [Issue #10](https://github.com/Myraxion/dion/issues/10)。

## 测试环境与配置

- **操作系统**：Windows 11 x64 (Build 26100)
- **Total Commander 版本**：Total Commander 11.58 64-bit (`11.58.0.0`)
- **TC 备注编码配置**：
  - 备注文件类型：`descript.ion`（带 UTF-8 BOM，`EF BB BF 0D 0A`）
  - 默认首选编码：`CommentPreferredFormat=4`（兼容纯文本，必要时 UTF-16/UTF-8；TC 对带 UTF-8 BOM 的既有文件固定保持 UTF-8 读写）
  - 多行扩展标记：`04 C3 82`（控制字符 04 引导的 TC UTF-8 换行与反斜杠转义标记）
- **测试 CLI 版本**：Dion v0.1.0 (Debug & Release)

## 真实 TC 用例与读取验收（TC → Dion）

测试直接复用 `.scratch/fixtures/` 中由 Total Commander 11.58 交互生成的真实目录与备注文件：

### 1. 顶层用例（`.scratch/fixtures/descript.ion`）
- `父文件夹1`：单行普通中文备注 `111测试`，Dion 正确读取，`extension: none`。
- `"父文件夹1 - 副本"`：带空格与中文的 Unicode 文件夹名（引号包裹），正文 `222测试`，Dion 正确解析文件名与正文，`extension: none`。
- `父文件夹2`：多行备注 `测试测试\n。`，带 `04 C3 82` 扩展标记，Dion 正确解码为 `测试测试\n。`，`extension: tc`。
- `dion list`：按原始记录顺序完整列出全部条目。

### 2. 尾部换行与连续空行（`父文件夹1/` 及子目录）
- `父文件夹1/config.json`：正文 `测试换行1\n\n`（连续双逻辑 LF），Dion 正确保留尾部连续两个逻辑换行。
- `父文件夹1/222/2.txt`：正文 `测试换行\n`（单个尾部逻辑换行），Dion 正确读取并保留尾部换行。
- `父文件夹1/222/1.txt`：正文 `测试换行\n\n。`（中间连续空行与句号），Dion 正确保留空行排版。

### 3. 反斜杠与转义字符密集样本（`父文件夹1/88/.env/.env`）
- 包含 `\n`（原始 `\\n`）、`\\n`（原始 `\\\\n`）、`/n`、`\r`（原始 `\\r`）、`\r\n`（原始 `\\r\\n`）及多行文本。
- Dion 正确将 `\\` 还原为 `\`，将 `\n` 解释为逻辑换行，字面量反斜杠与字母组合（如 `\n`、`\r`、`/n`）严格按字面还原，未发生误转义。

### 4. 特殊字符与复杂符号样本（`父文件夹1 - 副本/top`）
- 包含密集 ASCII 符号、双引号 `"`、Unicode 特殊字符（如 `)~Ì.,/Õvý"¿g»/Ä!...`）及多行转义。
- Dion 正确处理正文中的双引号，未误判为文件名边界；长文本与特殊字节往返一致。

### 5. 边缘用例（`.scratch/fixtures/边缘用例/`）
- 空记录 `empty_comment.txt`：`get` 成功且输出 0 字节，退出码 0，JSON 输出 `comment: ""`。
- 连续空格文件名 `"file   multiple   spaces.txt"`：双引号闭合与空格分隔正确识别。
- 单引号文件名 `"User's Notes.md"`：正确支持。
- 点文件 `.clang-format`：正确支持。
- 混合语言 `日本語_한국어_🚀.txt`：CJK 与 Emoji 字符集正确读取。
- 首尾空格保留 `tab_and_indent.txt`：首尾空格未被截断。

## 写入与生命周期验收（Dion → TC）

### 1. 三种输入来源与 TC 格式序列化
- **命令行参数**：单行文本（如 `C:\Windows\System32`）直接写入，不附加 TC 扩展标记；多行文本自动将 LF 转义为 `\n`、`\` 转义为 `\\` 并附加 `04 C3 82`。
- **stdin**：支持包含 CRLF/LF/CR 的标准输入，正确归一化并编码为 TC 多行格式。
- **文本文件（`--comment-file`）**：支持 UTF-8（带或不带 BOM）文本文件，尾部换行与空行完整保留并编码为 TC 多行格式。
- **实测 TC 识别**：通过 TC 命令行激活（`/O /S /L="..."`）将正在运行的 Total Commander 导航至包含 CLI 生成备注的目录，TC 成功识别并显示由 Dion 写入的备注。

### 2. 字节保留与记录顺序
- 在包含多条 TC 记录的文件中覆盖一条记录：仅目标记录原位被替换，其余记录（包括文件头 BOM、其他记录的扩展标记、行尾换行）字节 100% 保持未修改，顺序严格保持。
- 相同逻辑内容覆盖：返回 `changed: false`，且不触发文件写入，原文件哈希完全一致。

### 3. 显式删除与清理
- 删除多条记录中的某一条：仅移除目标记录字节，其余记录原样保留。
- 显式删除最后一条记录：彻底删除 `descript.ion` 文件（包括 BOM 和空白行），符合 Dion 规格。
- 剩余空记录或未知扩展记录时：删除目标记录后保留文件，不发生误清理。

## 规则策略区分说明（AC 6）

依据父规格（`docs/spec.md`），以下规则属于 Dion 明确选择的产品策略，并已通过测试严格验证，与实际 TC 观察区分如下：

1. **最后记录删除自动清理文件**：Dion 在显式删除最后一条记录后自动删除 `descript.ion`。TC 在通过界面清空备注时亦会清理空描述文件，Dion 的行为符合预期且具有确定的单元与集成测试保障。
2. **4096 字节长度限制包含行终止符**：Dion 将文件名、引号、正文、扩展标记及物理换行终止符全部计入 4096 字节。TC 编辑器对正文字符数有限制提示（511/4095），Dion 的物理长度限制策略能有效保证与 TC 文件缓冲区的兼容。
3. **末尾无物理换行的容忍与修复**：Dion 读取时宽容接受末条记录缺失换行；在追加新记录时自动补充 CRLF，并确保补充后原末条记录不突破 4096 字节。
4. **未知转义字符保留**：在带有 TC 标记的记录中，除 `\n` 和 `\\` 之外的组合（如 `\x`、`\t`）按字面量保留，不报错也不做非预期转换。
5. **不区分大小写匹配**：记录名称匹配固定不区分大小写，大小写重复记录直接拒绝，避免破坏性覆盖。
