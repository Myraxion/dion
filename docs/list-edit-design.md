# List 展示与外部编辑增强设计

状态：两轮决策及测试边界已确认，已汇总为[增强规格](list-edit-spec.md)并发布为 [Issue #12](https://github.com/Myraxion/dion/issues/12)；本文保留确认时的设计示例与调研背景。实施进度见该 Issue，当前已实现行为以[行为契约](spec.md)为准。

2026-10-09 后续变更：`list` 改为默认跳过错误并汇总诊断，JSON 增加 `errors` 数组；有跳过错误时输出有效记录并返回退出码 1，起始目录无法访问仍直接失败。下文原有的整次查询失败设计及 JSON 字段不变规则已由[当前契约](spec.md#命令与路径)取代。

2026-10-10 后续变更：下文 Unicode 小写名称匹配和重复检测由[Windows 原生名称比较设计](windows-name-comparison-design.md)取代，列表目录识别及树节点合并同步使用该比较器；自然展示排序继续使用 `StrCmpLogicalW`。

## 已确认的需求

- `list` 文本有三种展示模式：默认双栏、`--long`（`-l`）单栏、`--tree` 树状；`--tree` 与 `--long` 互斥。全部显示完整备注。
- 默认双栏按本次名称的显示宽度计算左栏，两栏相隔两个空格；中文及常见宽字符参与宽度计算。多行正文后续行对齐右栏，不截断或按终端宽度主动折行，保留正文原有换行及空白。
- `--long` 名称独占一行，每行正文固定缩进四个空格，包括空行。保留正文原有空行和末尾换行，再额外添加一个记录间空行；正文自带末尾空行时，视觉间距可以更大。
- `--recursive`（`-r`）读取起始目录及其子目录中的备注记录，保留孤立记录。每个目录先输出自身全部已排序记录，再按子目录名称自然升序逐个深度优先递归。
- `--tree` 自动开启递归，仅展示备注记录及连接它们所需的辅助目录节点；子节点紧跟所属目录展开。不显示起始目录根节点。
- 树模式在节点名称后用两个空格连接正文，后续正文行对齐该节点正文的起点，不设全树统一右栏，不额外添加记录间空行。辅助目录节点只显示名称。目录自身的备注和连接后代所需的节点合并为同一个节点，先显示自身完整正文，再展开子节点。
- 记录排序以目录优先，然后各组内部 Windows 不区分大小写自然升序。孤立记录归入文件组，不加目录标记。目录符号链接和 Junction 自身归入目录组，但遍历中不进入它们。
- 自然排序采用 Windows `StrCmpLogicalW`，比较相等时按原名称的 UTF-16 序列比较。接受系统排序细节随 Windows 版本变化，不承诺跨版本完全一致；不改变现有 Unicode 小写名称匹配和重复检测。每层树节点（包括辅助目录节点）也遵循目录优先规则。
- 用户显式指定的起始目录可以是符号链接或 Junction，继续读取其内部；不进入链接的规则只限制途中遇到的子目录。其他类型的目录重解析点不额外排除。
- 文本目录名称末尾添加 `\`。JSON 名称不加目录类型标记，保持 `entries` 数组及每条记录的 `name`、`comment`、`extension` 字段。
- 递归列表的名称使用相对于起始目录的路径和 Windows 分隔符，例如 `sub\a.txt`；起始目录内仍是 `a.txt`。树状 JSON 输出普通递归列表，排除辅助目录节点；JSON 忽略文本排版选择。`--tree --long` 的互斥规则仍适用。
- 现有解析器接受的非普通名称（例如含路径分隔符或点组件）继续是所在备注文件中的一个完整名称，不据此创建层级或访问其他目录。无法对应普通条目的名称按孤立记录处理。树的层级来自实际遍历的目录。
- 排序只影响输出，不修改备注文件的内容或记录顺序。
- 递归遇到无法访问的目录、编码错误或格式错误，整次查询失败，stdout 为空；没有备注文件的目录仍继续遍历。
- `set --edit` 为第四种正文输入来源，与参数正文、`--stdin`、`--comment-file` 互斥。编辑器预填已有正文或空文本，正常退出后严格读取 UTF-8，沿用已有输入标准化与设置规则。
- 编辑器选择顺序是 `VISUAL`、`EDITOR`、Windows 记事本；空环境变量视为未配置。环境变量值作为 Windows 命令行，支持带引号的程序路径和参数，在末尾追加临时文本路径。编辑器需要等待用户编辑完成再退出，例如 VS Code 配置为 `code --wait`；非零退出码视为失败，不修改备注。
- 操作成功后删除编辑临时文本；启动、编辑或保存备注失败时保留已经创建的临时文本，在 stderr 报告恢复路径。JSON 错误沿用现有结构，在错误文案中包含路径，不新增字段。
- 编辑后空字符串按现有 `remove` 规则删除；记录不存在则成功且不写入。仅含空格、Tab 或换行仍是输入错误；其他输入来源继续拒绝空白正文。
- 校验顺序：严格读取 UTF-8、接受可选 BOM并统一逻辑换行；空字符串走删除；非空正文走现有设置校验（空白或非法控制字符拒绝、目标必须存在、未知扩展拒绝）；校验通过后才比较逻辑正文，相等则成功且不写入。
- 已有空记录即使打开后未编辑也会删除；已有纯空白正文原样退出仍报输入错误；未知扩展原样退出仍报 `unknown_extension`，但清空可以删除。孤立记录可以通过清空删除，非空设置仍要求目标存在。
- 编辑期间检测到原备注文件内容变化，报 `content_changed`，不覆盖、不合并，沿用单写者规则。
- 编辑前读取备注文件快照，编辑器正常退出后重新检查内容（包括文件的出现或消失），无变化操作也需要经过这个检查。提交时继续沿用已有变化检查和提交方式；不增加并发协调、重试或合并，不承诺消除检查与提交之间的竞态。
- 支持 `dion --help`、`dion -h`、`dion help` 总览和 `dion <command> --help`、`dion <command> -h`、`dion help <command>` 子命令帮助。帮助为中文，命令和参数名保留英文，包括用途、参数、默认行为及常用示例。
- 帮助写 stdout，退出码 0，带 `--json` 时仍显示文本帮助。`--tree --long` 即使带 `--json` 也报参数互斥错误。

## 展示与顺序示例

假设起始目录有 `docs` 目录，目录自身备注为“文档目录”；`file2.txt`、`file10.txt` 有备注，`docs` 内有 `guide.txt` 的多行备注。

直接双栏：

```text
docs\       文档目录
file2.txt   第二份
file10.txt  第十份
```

普通递归的记录顺序为 `docs`、`file2.txt`、`file10.txt`、`docs\guide.txt`，其中文本目录标记仅适用于 `docs`，JSON 的 `name` 为上述无末尾标记值。双栏递归的左栏宽度按本次所有相对名称计算；单栏递归使用相同顺序。

树状文本：

```text
├─ docs\  文档目录
│  └─ guide.txt  第一行
│                第二行
├─ file2.txt  第二份
└─ file10.txt  第十份
```

去掉 `docs` 自身备注后，树仍保留 `docs\` 作为辅助目录节点；普通列表和 JSON 不添加这个辅助节点。目录及后代均无备注时不出现在树中。

## 验收场景

- 默认双栏包含中文、宽字符、不同长度名称和多行正文，验证右栏对齐和完整正文；长名称不截断、不主动折行。
- 单栏验证四空格缩进、空正文、连续空行、末尾换行和记录间空行；树模式验证分支连接、完整多行正文、辅助节点、目录备注合并和无关节点排除。
- 直接列表验证目录优先、文件目录混排、`file2` 在 `file10` 前及比较相等时的次级排序；三种平面输出（双栏、单栏、JSON）顺序相同。列表操作前后备注文件字节一致。
- 普通递归验证父目录全部记录先于子目录记录、子目录自然顺序、相对路径和孤立记录保留；树文本保持父子结构，树 JSON 与普通递归 JSON 相同。
- 链接和 Junction 子目录自身备注可列出，内部不遍历；显式指定链接起始目录则读取内部。无备注文件的中间目录仍遍历。
- 子目录访问失败或坏备注文件使整次查询失败，stdout 为空，不泄漏已读取的部分结果。
- 非普通记录名称保持为单个完整名称，不改变备注解析格式和名称匹配规则。
- 外部编辑器使用受控测试程序，验证预填正文、等待退出、环境变量优先级、含空格程序路径及参数、UTF-8 BOM和换行标准化。
- 编辑非空有效正文与现有逻辑正文相同，成功且不写入；空字符串删除已有记录、清理最后记录，无记录则成功且不创建备注文件。
- 编辑已有空记录原样退出仍删除；纯空白、非法 UTF-8、非法控制字符不修改备注。未知扩展非空设置拒绝，清空允许；孤立记录非空设置拒绝，清空允许。
- 编辑器启动或退出失败不修改备注；错误保留编辑临时文本并报告路径，成功清理。编辑期间修改、创建或删除原备注文件触发冲突检查，包括编辑正文未变化的情况。
- 总览和子命令帮助的各入口成功输出中文文本；`--tree --long` 和互斥正文输入来源报参数错误，JSON 下同样校验。

## 实施时需要验证的事实

- 现有 storage 仅在实际写入或删除时检测原内容，no-op 不重读；因此编辑模式需要单独检查编辑等待期间的快照变化，不能直接重新调用普通 set/remove 丢掉编辑前的基线。
- 默认记事本必须真实验证等待行为，受控编辑器测试不能替代该验收。当前开发机器的 `notepad.exe` 由系统配置重定向至 Notepad4，不能作为微软原生记事本的验收证据。现代记事本有标签页功能，但未找到官方承诺其启动进程退出就代表当前文本编辑完成；实现不能仅凭退出 API 的使用就宣称这项行为已经验证。
