# Dion 第一版开发规格

本文件汇总设计讨论中逐项确认的第一版产品规则。按 to-spec 技能整理的正式实施规格见 [本地规格](spec.md) 和 [GitHub Issue #1](https://github.com/Myraxion/dion/issues/1)；尚未开始实现。

## 已确认的边界

- 第一版提供查看单条备注、列出目录备注、设置或覆盖备注、删除备注。
- 第一版只读写 UTF-8；其他编码明确报错。
- 支持 Windows 10/11 x64 的本地文件系统。
- 允许编译期 Rust 依赖；交付单个 exe，用户无需额外安装运行时。
- 开发语言为 Rust；服务命令行用户、Agent 与脚本。

## 已确认的操作规则

- 查看、列出、删除以备注记录为准，不要求所指文件或文件夹存在。
- 设置备注要求目标文件或文件夹存在。
- 设置空备注直接报错，不新增空记录，也不覆盖已有备注；只有显式删除操作才移除备注记录。
- 修改一条备注时，仅修改目标记录，其余内容按原字节保留。见 [ADR-0001](adr/0001-preserve-unmodified-bytes.md)。
- 接受的备注文件必须带 UTF-8 BOM；无 BOM 文件拒绝读写。
- 设置禁止空字符串及纯空白内容；不裁剪正文首尾空白，逻辑换行按下文统一为 LF。已有空记录允许读取。
- 已识别的格式错误导致整次操作报错：读取不输出正常结果，写入不修改文件；错误报告文件、行号和原因。
- 名称匹配固定不区分大小写；仅大小写不同的两条记录视为冲突，不分别支持区分大小写目录中的此类名称。
- 未知程序扩展：读取 `04` 前的普通正文，设置该记录时报“未知扩展，无法修改”，显式删除允许移除整条记录。未知扩展本身不归为坏行；未修改记录的扩展按原字节保留。
- 完成适用校验后，设置的逻辑正文与已有备注相同则成功但不写文件，返回 `changed:false`；不借此统一原记录格式。未知扩展的设置仍按上述规则拒绝。
- 修改保持原记录位置，新增追加到末尾，删除仅移除目标记录；列出时保持原始顺序，不自动排序。

## 已确认的命令形态

```text
dion get <path>
dion list [directory]
dion set <path> <comment>
dion set <path> --stdin
dion set <path> --comment-file <file>
dion remove <path>
```

- `get/set/remove` 操作指定文件或文件夹自身的备注，使用它所在父目录的 `descript.ion`。
- `list` 列出指定目录备注文件中的记录，省略目录时使用当前目录。
- `get ./photos` 查看 photos 文件夹自身的备注；`list ./photos` 列出 photos 内部条目的备注。
- 支持本地普通相对路径、绝对路径及 Windows 长路径，包括扩展本地路径 `\\?\D:\资料\...`。
- 文件或文件夹符号链接、目录联接按输入路径对应条目自身操作，使用它所在父目录的备注文件，不转而操作链接目标的备注。
- 磁盘根可以 `list`；根本身没有用于存放自身备注的父目录，对其执行 `get/set/remove` 报参数错误。
- `list` 只读取备注记录，不检查目标是否存在，不枚举目录条目，不递归。

## 已确认的输入输出契约

- 设置备注支持命令行正文参数、`--stdin`、`--comment-file <file>` 三种来源，每次只能选择一种。
- 命令行正文不自行解释字面量 `\n`；实际换行由多行参数、stdin 或备注文本文件提供。
- stdin 和备注文本文件使用 UTF-8，接受可选 BOM，不裁剪输入末尾换行。这与必须有 BOM 的 `descript.ion` 输入规则不同。
- 设置正文拒绝实际的 NUL 和 `04` 控制字符，避免与格式控制信息混淆；Tab 等正常排版内容保留。
- 输入中的 CRLF、LF、CR 均归一为逻辑 LF，保留空行和末尾换行数量；写入多行格式后无法逐字节还原原输入换行类型。
- 默认输出方便人阅读；显式 `--json` 提供稳定机器输出，不根据是否接入管道自动改变格式。
- `get` 默认只输出备注正文，使用 LF 作为逻辑换行，不额外追加换行；已有空记录输出零字节但成功。
- `list` 默认输出名称和完整备注的可读列表；`set/remove` 默认成功时不输出。
- 四个命令均支持 JSON 结果；错误写 stderr，指定 `--json` 时错误也采用 JSON。
- `get` 未找到记录（包括备注文件不存在）时 stdout 为空，退出码 3；已有空记录读取成功，退出码 0。
- `list` 的备注文件不存在时成功返回空列表。
- `remove` 的记录或备注文件不存在时成功、不修改、不创建文件。
- 退出码：0 成功，1 格式/编码/权限/网络等操作错误，2 参数错误，3 `get` 未找到记录。

### JSON 结构

成功结果写 stdout，错误写 stderr。JSON 使用 UTF-8、无 BOM，文档以 LF 结束；`comment` 字段不附加额外换行。错误时 stdout 为空，包括使用 `--json` 的未找到记录情况。

`get` 返回一条记录，`name` 保留记录中的原始名称拼写：

```json
{"name":"a.txt","comment":"备注正文","extension":"none"}
```

`list` 返回记录数组；空列表为 `{"entries":[]}`：

```json
{"entries":[{"name":"a.txt","comment":"备注正文","extension":"none"}]}
```

`extension` 为 `none`、`tc` 或 `unknown`，表示记录的程序扩展解释状态。未知扩展的 `comment` 为 `04` 之前的普通正文。

`set/remove` 返回是否实际修改；相同备注的设置、没有目标记录的删除返回 `false`：

```json
{"changed":true}
```

错误结构示例：

```json
{"error":{"code":"invalid_format","message":"引号未闭合","file":"D:\\data\\descript.ion","line":3}}
```

`code` 是供脚本判断的稳定类型标识，`message` 供人阅读；`file/line` 仅在适用时提供。行号按备注文件的物理行计算，包括 BOM 后的文件头空行。

## 已确认的文件生命周期与格式

- 首次成功设置时自动创建 `descript.ion`，文件头采用 `EF BB BF 0D 0A`。
- 显式删除最后一条记录后自动删除备注文件；这是保留未修改字节规则的明确例外。已有空记录和含未知扩展的记录也属于记录，不能只计算非空正文。
- 自动删除最后一条记录后的备注文件为 Dion 产品规则；用户期望与 TC 默认行为一致，但尚未取得 TC 官方对此默认行为的明确保证。
- 读取要求 UTF-8 BOM，不强制 BOM 后有空行；物理记录换行接受 CRLF、LF、CR，并允许最后一条记录缺少终止换行。
- 新增或修改的目标记录以 CRLF 结束，其余内容保留原字节。
- 若原文件最后一条记录没有终止换行，追加新记录前补充必要的 CRLF 分隔符，保留原文件已有字节；补充分隔符后的既有记录仍须满足 4096 字节上限，否则报错且不修改。
- 文件名含空格时用双引号包围，文件名后使用一个空格分隔备注正文。
- 多行正文写成一条物理记录：逻辑 LF 编码为字面量 `\n`，反斜杠编码为 `\\`，附加 TC UTF-8 标记 `04 C3 82`。
- 只有带 TC 标记的记录才解释 `\n` 和 `\\`；其他反斜杠组合按字面保留。此项对未知转义的处理是 Dion 产品规则，未宣称已核验 TC 的相同行为。
- 单条记录按序列化后的 UTF-8 字节计数，包含文件名、引号、分隔空格、正文、扩展和行终止符，最多 4096 字节；超限报错，不截断。
- 最后一条记录缺少终止换行的接受行为，以及 4096 字节包含行终止符，均为已确认的 Dion 产品规则；未冒充已完整核验的 TC 行为。

## 已确认的写入与并发范围

- 先在同目录写完整临时文件，再提交替换；不直接截断原文件，也不在替换失败后回退为原地覆盖。见 [ADR-0003](adr/0003-temporary-file-and-single-writer.md)。
- 格式和输入校验失败不修改文件；提交阶段的 I/O 错误可能出现部分完成状态，不承诺所有失败均保持原文件完全不变。
- 第一版按单写者使用，不保证多个进程同时修改同一备注文件。
- 检测到占用或内容变化时报错，不自动重试或合并；内容变化检测不等于多写者协调保证。
- 新建备注文件默认设置隐藏属性；修改已有文件时保留其属性、创建时间和访问权限。
- 对只读备注文件的修改或删除报错，不自动解除只读；只读属性不阻止读取。不修改被备注文件或文件夹的属性。
- 默认不生成常驻 `.bak` 文件，第一版不增加备份选项；正常成功后清理临时文件，失败时保留恢复所需文件并报告位置。

## 已确认的性能验收方式

- 优先冷启动和普通目录操作，以 100 条和 1 万条记录建立本地基准。
- 记录启动、查询、列出、写入耗时，峰值内存及 exe 体积。
- 取得 Release 构建基线后再确定耗时门槛；exe 体积暂以不超过 5 MiB 为目标。

## 验收场景

用户已确认以真实 CLI 进程作为功能测试入口：在隔离目录运行命令，检查 stdout、stderr、退出码、备注文件字节与属性。本地性能使用同一个 exe 测量；完整测试决定见实施规格。

- 合法样本的单行、多行、反斜杠、Unicode 名称、首尾空白、空记录、仅头文件均可正确读取。
- 修改一条记录后，其他记录与文件原有内容按原字节保留；相同内容设置不改变文件。
- 非法 UTF-8、缺 BOM、引号未闭合、超长记录、名称冲突导致整次操作失败，正常输出为空且文件不变。
- 空白设置、正文包含保留控制字符、未知扩展设置报错；未知扩展读取和显式删除遵循上述契约。
- 设置需要目标存在，孤立记录可以读取和删除；不存在的备注记录删除成功且不创建文件。
- 删除最后一条实际记录后删除备注文件；已有空记录和未知扩展记录仍计入剩余记录。原本无记录的文件不会因无效目标删除请求而被清理。
- 三种输入来源互斥，中文及实际多行通过 UTF-8 输入正确传递；文本和 JSON 输出、stderr、退出码符合契约。
- 验证本地文件的读取、创建、替换、删除、属性保留和权限错误。
- 记录 Release 性能基线及 exe 体积；具体耗时门槛在基线取得后确认。

这些验收场景供实现阶段使用，当前尚未执行应用测试或性能测量。

## 范围与已知限制

- 第一版提供四个基础命令；编码转换、递归搜索、批量导入导出、自动清理、文件复制/移动/重命名及备份选项不在本版范围。
- UNC、SMB、WebDAV 和网络映射盘不作兼容性承诺，不设共享验收或性能要求。现有文件操作可能接受这些路径，但不保证可用；不主动识别或拒绝网络存储。过去的实测仅作[历史记录](archive/unc-validation.md)。
- exe 单文件分发允许编译期 Rust 依赖，不要求用户额外安装运行时。
- 尚未完整核验的 TC 行为已在相关规则旁标出，不影响已确认的 Dion 产品选择。

## 样本调查

- `.scratch/fixtures/`：7 个 UTF-8 备注文件，16 条合法与边缘记录，包含空备注、多行和反斜杠、Unicode 名称、仅头文件；文件头均为 `EF BB BF 0D 0A`。
- `.scratch/fixtures_malformed/`：5 个样本，分别为未闭合引号、超长行、缺失 BOM、非法 UTF-8，以及仅大小写不同的重复名称。
- 无 BOM 样本正文为有效 UTF-8，但按已确认的 BOM 策略拒绝读写。
- 仅大小写不同的两条记录按已确认的名称匹配规则视为冲突。
