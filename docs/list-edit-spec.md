## Problem Statement

当前列表使用名称加正文的连续输出，长正文与下一条记录不易区分；记录按备注文件的原始顺序输出，无法自然查找名称，也无法汇总子目录中的备注。用户需要完整、清晰且可预测的文本列表，同时继续使用稳定的 JSON 字段。

多行备注只能通过命令参数、stdin 或文本文件设置，缺少直接打开已有正文进行编辑的入口。命令还缺少完整帮助，用户难以发现输入来源、默认行为和常用用法。

## Solution

为列表提供三种文本展示模式：默认双栏、单栏 `--long`（`-l`）、树状 `--tree`，三种模式均展示完整备注。增加普通递归 `--recursive`（`-r`），按规定的目录遍历顺序汇总备注记录；树模式自动递归并保持父子结构。文本标识目录，记录自然排序，JSON 保持结构和字段不变。

为设置增加 `--edit`，在外部编辑器中修改预填的正文；有效正文未变化时不写入，清空正文时删除，编辑或校验失败时保留恢复文本。补齐中文总览和子命令帮助。

## User Stories

1. 作为查看备注的用户，我希望默认按名称和备注双栏显示，以便快速扫描名称及其说明。
2. 作为查看多行备注的用户，我希望后续正文行对齐右栏，以便识别正文归属。
3. 作为使用中文和宽字符名称的用户，我希望左栏按显示宽度计算，以便对齐常见 Unicode 名称。
4. 作为查看长正文的用户，我希望使用 `--long` 或 `-l`，以便名称独占一行、正文缩进并分隔记录。
5. 作为需要完整信息的用户，我希望正文不被截断或主动折行，以便保留空白、空行和末尾换行。
6. 作为浏览多个目录的用户，我希望使用 `--recursive` 或 `-r` 汇总备注，以便一次查看整个目录范围。
7. 作为递归查询的用户，我希望结果名称是相对于起始目录的路径，以便定位备注所属条目。
8. 作为递归查询的用户，我希望当前目录的全部记录先于子目录记录，以便顺序可预测。
9. 作为查询备注的用户，我希望孤立记录仍被列出，以便看到尚未清理的说明。
10. 作为浏览目录关系的用户，我希望 `--tree` 自动递归并保持父子结构，以便理解备注所在层级。
11. 作为树状查询的用户，我希望仅显示备注记录及必要的辅助目录节点，以便减少无关信息。
12. 作为树状查询的用户，我希望目录自身的备注与展开节点合并，以便避免同一目录重复出现。
13. 作为树状查询的用户，我希望多行正文紧随所属节点且对齐其正文起点，以便识别说明归属。
14. 作为查看列表的用户，我希望目录优先、各组内部按 Windows 不区分大小写自然升序排序，以便按熟悉的顺序查找。
15. 作为查看列表的用户，我希望 `file2` 在 `file10` 前，以便数字名称按数值顺序排列。
16. 作为查看文本列表的用户，我希望目录名称末尾有反斜杠，以便区别文件和目录。
17. 作为依赖原始备注文件的用户，我希望查询排序不修改文件字节和记录顺序，以便只读操作没有写入副作用。
18. 作为递归查询的用户，我希望不进入途中遇到的目录符号链接或 Junction，以便遵循指定的遍历边界。
19. 作为查看链接自身备注的用户，我希望链接目录的记录仍可列出，以便不遗漏其说明。
20. 作为显式查询链接目录的用户，我希望指定链接为起始目录时仍读取其内部，以便保留现有用法。
21. 作为脚本用户，我希望 JSON 保持 `entries`、`name`、`comment`、`extension`，以便继续解析现有结果。
22. 作为脚本用户，我希望默认双栏、单栏和 JSON 共用普通列表顺序，以便展示选择不改变平面记录顺序。
23. 作为脚本用户，我希望树模式的 JSON 等于普通递归 JSON，以便不必处理辅助目录节点。
24. 作为查询用户，我希望递归遇到访问或备注格式错误时整次失败且 stdout 为空，以便不把部分结果当成完整结果。
25. 作为维护已有备注文件的用户，我希望非普通记录名称仍作为一个完整名称读取，以便新增查询能力不改变解析兼容性。
26. 作为编辑备注的用户，我希望 `set --edit` 预填已有正文或空文本，以便直接修改或创建备注。
27. 作为使用自选编辑器的用户，我希望按 `VISUAL`、`EDITOR`、Windows 记事本的顺序选择编辑器，以便沿用个人配置。
28. 作为使用带参数编辑器的用户，我希望配置支持引号和参数，以便使用含空格的程序路径或 `code --wait`。
29. 作为编辑备注的用户，我希望命令等到编辑完成并正常退出再读取文本，以便不会提前提交。
30. 作为编辑备注的用户，我希望有效正文的逻辑内容未变化时不写入，以便保留原文件字节和时间等状态。
31. 作为删除备注的用户，我希望在编辑器中清空正文即可删除，以便操作符合直觉。
32. 作为编辑孤立记录的用户，我希望清空可以删除，但设置非空正文仍要求目标存在，以便沿用设置和删除的各自规则。
33. 作为避免误删的用户，我希望纯空格、Tab 或换行仍报输入错误，以便无效正文不会触发删除。
34. 作为 stdin 或正文文件输入的用户，我希望这些来源继续拒绝空白正文，以便其契约不因外部编辑而改变。
35. 作为编辑备注的用户，我希望 UTF-8、可选 BOM、逻辑换行及未知扩展遵循已有规则，以便不同输入来源一致。
36. 作为编辑已有空记录的用户，我希望原样关闭也按清空规则删除，以便空字符串的删除语义一致。
37. 作为编辑备注的用户，我希望启动、编辑或校验失败时不提交正文，并能找回临时文本，以便保留编辑成果。
38. 作为编辑期间可能遇到其他修改的用户，我希望检测原备注文件的字节或存在性变化，以便不覆盖其他修改。
39. 作为使用自动化脚本的用户，我希望编辑成功继续返回现有 `changed` 布尔值，以便判断是否发生实际修改。
40. 作为首次使用命令的用户，我希望通过 `--help`、`-h` 或 `help` 查看中文总览，以便发现命令和默认行为。
41. 作为使用某个子命令的用户，我希望通过其 `--help`、`-h` 或 `help <command>` 查看参数与示例，以便直接完成操作。
42. 作为命令行用户，我希望互斥的展示模式和正文来源报参数错误，以便及时发现用法错误。

## Implementation Decisions

- 沿用现有 CLI 参数解析、备注解析与局部修改、Windows 文件提交职责。增加列表采集/排序/呈现和外部编辑职责，优先具体类型与普通函数，保持简单，不为未提出的需求增加通用框架。
- `list` 目录参数仍可省略，省略时使用当前目录；不带递归选项的查询只列出自身备注文件的记录。为了识别目录类型和排序，可以查询记录所指的普通条目。
- 文本模式为默认双栏、`--long`（`-l`）、`--tree` 三选一；`--tree` 与 `--long` 互斥，即使使用 `--json` 也报参数错误。`--recursive`（`-r`）与默认双栏或单栏组合；树模式自动开启递归。
- 默认双栏按本次全部显示名称（包括递归相对路径及文本目录标记）的显示宽度计算左栏，以两个空格分隔左右栏；中文及常见宽字符参与宽度计算。后续正文行对齐右栏。不根据终端宽度截断或主动折行。
- 单栏名称独占一行，每行正文固定缩进四个空格，包括空行。保留正文原有空行和末尾换行，再额外添加一个记录间空行；正文自带末尾空行时允许更大视觉间距。
- 树模式不显示起始目录根节点；节点使用树分支连接，名称后两个空格接正文，后续正文行对齐该节点的正文起点，不设全树统一右栏，也不额外添加记录间空行。
- 树只显示备注记录和连接它们所需的辅助目录节点。目录自身有备注时合并为一个节点，先显示自身完整正文，再展开子节点；辅助目录节点只显示名称。无备注且没有相关后代的目录不显示。
- 排序先按目录组、文件组分组，再在组内按名称自然升序。孤立记录归入文件组，不添加目录类型标记。目录符号链接及 Junction 自身归入目录组。
- 自然排序采用 Windows `StrCmpLogicalW`，比较相等时按原名称的 UTF-16 序列比较。接受系统排序细节随 Windows 版本变化，不承诺跨版本完全一致。排序不改变现有 Unicode 小写名称匹配和重复检测。
- 普通递归每个目录先输出自身全部已排序记录，再按子目录名称自然升序逐个深度优先递归。默认双栏、单栏和 JSON 共用直接或普通递归的记录顺序。树按每层兄弟节点排序，目录优先也适用于辅助节点，子节点紧跟所属目录展开。
- 文本目录名称末尾添加 `\`；JSON 名称不添加目录标记。递归名称使用相对于起始目录的路径和 Windows 分隔符，起始目录内的名称不加 `.` 前缀。记录名称保留既有拼写。
- 现有非普通记录名称继续作为所属备注文件中的一个完整名称，不解释其路径分隔符或点组件，不据此创建层级或访问其他目录；无法对应普通条目的名称按孤立记录处理。树层级来自实际遍历的目录。
- 递归途中不进入目录符号链接或 Junction，但可列出其自身备注。显式起始目录可以是符号链接或 Junction，继续读取内部；其他类型的目录重解析点不额外排除。
- 没有备注文件的目录仍递归其子目录。无法访问目录或遇到编码、格式错误时，整次操作失败且 stdout 为空，包括此前已读取正常记录的情况。不跳过错误目录，不输出部分成功结果。
- JSON 列表仍是包含 `entries` 数组的对象，每条记录只使用现有 `name`、`comment`、`extension` 字段。树 JSON 与普通递归 JSON 相同，不包含辅助目录节点。JSON 忽略文本排版选择，但仍校验互斥选项。
- 所有列表操作只改变输出，不修改备注文件的字节、记录顺序或格式。保留现有空记录、未知扩展读取、编码、长度限制及错误契约。
- `set --edit` 是第四种正文输入来源，与参数正文、`--stdin`、`--comment-file` 互斥。编辑前解析原备注文件并捕获原始字节/存在性快照，编辑临时文本预填已有逻辑正文或空文本。
- 编辑器选择顺序为非空 `VISUAL`、非空 `EDITOR`、Windows 记事本。配置值作为 Windows 命令行，支持带引号的程序路径和参数，末尾追加编辑临时文本路径。必须等到编辑完成并正常退出后读取；需要等待参数的编辑器由配置提供，例如 `code --wait`。
- 编辑器启动或退出失败时不提交备注。成功后删除编辑临时文本；启动、编辑、输入校验或保存失败时，保留已创建的编辑临时文本，并在 stderr 报告恢复路径。JSON 错误继续使用现有结构，在文案中包含路径，不新增字段。
- 编辑器正常退出后重新读取原备注文件，与编辑前快照比较，包括文件出现或消失。检测到等待期间变化时返回 `content_changed`，即使编辑正文未变化也不跳过检查；不能重新捕获基线后调用普通设置/删除而丢失编辑前状态。
- 编辑文本严格使用 UTF-8、接受可选 BOM，CRLF、CR 统一为逻辑 LF，不裁剪正文。空字符串先走现有删除规则；非空正文先进行现有输入、目标存在性和未知扩展校验，校验通过后再比较逻辑正文，相等则成功且不写入。
- 编辑清空时，记录不存在则成功且不创建或修改备注文件；删除最后一条记录仍删除备注文件。已有空记录即使原样关闭也会删除。仅含空格、Tab 或换行仍报输入错误，非法控制字符仍拒绝。
- 未知扩展记录可以清空删除，非空设置（包括原样关闭）仍返回 `unknown_extension`。孤立记录可以清空删除，非空设置仍要求目标存在。参数正文、stdin 和正文文件继续拒绝空白正文。
- 文本设置/删除成功仍静默，JSON 仍只含 `changed` 布尔值。编辑错误沿用现有错误代码及退出码。继续使用既有局部修改、最后记录删除、只读属性和 Windows 文件提交规则。
- 总览支持 `dion --help`、`dion -h`、`dion help`；子命令支持 `dion <command> --help`、`dion <command> -h`、`dion help <command>`。帮助为中文，命令和参数名保持英文，包含用途、参数、默认行为和常用示例。
- 帮助写 stdout、退出码 0；带 `--json` 时仍显示文本帮助。互斥选项继续遵循参数错误契约。
- 实施时同步更新已实现行为的契约、用户文档和现有回归断言。目录查询与排序会替换现有“不检查目标、不递归、列表保持原始顺序”的规定；不改变备注文件的记录顺序和保存方式。

## Testing Decisions

- 用户已确认沿用最高层的真实 CLI 黑盒集成测试边界：在隔离目录运行真实程序，检查 stdout、stderr、退出码，以及最终文件字节、存在性、时间和 Windows 属性。测试外部行为，不依赖内部函数划分或排序实现步骤；不新增测试专用产品接口。
- 复用既有列表、设置、删除和路径测试的隔离目录、进程运行、JSON 解析、文件状态观察方式。测试覆盖 CLI 参数与帮助、列表采集/呈现、外部编辑，以及它们与备注格式和存储提交的组合；继续使用已有格式和提交回归测试。
- 双栏验证动态宽度、中文和宽字符、多行正文、首尾空白、空记录、连续空行、末尾换行及长名称。单栏验证四空格缩进和记录分隔。树验证分支、正文对齐、辅助节点、目录备注合并及无关节点排除。
- 验证目录优先、文件目录混排、`file2` 在 `file10` 前和次级比较；默认双栏、单栏及 JSON 顺序一致。确认查询前后备注文件字节与文件状态不变。
- 递归验证先输出当前目录全部记录再进入子目录、子目录自然顺序、相对路径、孤立记录、无备注文件的中间目录。树验证父子关系；树 JSON 与普通递归 JSON 相等，无辅助节点和新增字段。
- 路径测试覆盖普通目录、符号链接及 Junction：途中链接自身备注可列出，内部不进入；显式链接起始目录则读取内部。非普通记录名称保持单一节点，不被用于额外路径访问。
- 递归中后续目录访问失败或备注文件编码/格式错误，验证退出码、诊断文件/行信息和 stdout 为空，不泄漏部分结果。
- 使用受控外部编辑器程序，通过真实进程验证预填正文、等待退出、环境变量优先级、命令参数和含空格路径、成功/失败退出、UTF-8 BOM及换行标准化。默认 Windows 记事本另做真实验收，受控程序不替代它的等待行为验证。
- 编辑有效正文相同则验证 `changed:false`、字节及时间不变；编辑清空覆盖普通记录、已有空记录、最后记录、无记录和孤立记录。纯空白、非法 UTF-8、非法控制字符、未知扩展非空编辑验证错误和未提交；stdin 与正文文件空白拒绝继续回归。
- 编辑器启动、退出、校验或保存失败验证编辑临时文本保留及恢复路径；成功验证清理。保存失败按既有提交契约观察，不将“编辑器失败不提交”扩大成所有提交阶段 I/O 故障都能回滚。
- 受控编辑器在编辑等待期修改、创建或删除原备注文件，验证 `content_changed` 和不覆盖；包含编辑正文未变化的 no-op 场景，确保检查覆盖此分支。
- 帮助各入口验证用途、参数、默认行为、常用示例、中文文本、stdout 和退出码；带 JSON 的帮助仍是文本。互斥展示模式、互斥正文来源和其他既有参数错误在文本及 JSON 下均回归。
- 执行项目既有 Windows 统一检查入口，完成格式、clippy、完整测试和 Release 构建；沿用单文件交付及现有体积目标，不设新的性能阈值。

## Out of Scope

- 改写或排序备注文件内容、自动清理孤立记录、改变名称匹配、重复检测或备注格式兼容性。
- 搜索、筛选、批量编辑、导入导出、复制移动重命名时的备注同步，以及与备注无关的文件树展示。
- 自动正文截断、按终端宽度折行、自定义颜色主题、交互式树导航或内置编辑器。
- 修改 stdin、正文文件或参数正文的空白拒绝规则；自动解读或改写未知程序扩展。
- 自动推断孤立记录原来的目录类型；依据记录名称中的路径分隔符重建目录层级。
- 跳过错误目录并返回部分成功结果、自动重试或合并、多写者协调，以及检查到提交之间的完整事务保证。
- 扩大既有平台、编码和网络存储兼容性承诺；增加常驻备份、后台服务或文件系统监控。
- 本规格不包括任务拆分或功能实现。

## Further Notes

- 已确认三种文本模式，树与单栏互斥；本规格汇总此前两轮讨论和已经确认的测试边界，无需重新分诊。
- 保留未修改内容的原始字节、固定 Unicode 小写名称匹配、单写者及同目录临时文件提交的既有 ADR 继续有效。Windows 自然排序只影响输出。这些可独立调整的 CLI 行为不另建架构 ADR。
- 现有存储变化检查仅覆盖实际写入或删除，不覆盖 no-op；外部编辑需要额外的编辑前后快照比较，而不是仅复用提交时检查。
- 默认记事本等待行为尚需原生 Windows 10/11 环境验收。当前开发机器的记事本入口被系统配置重定向至 Notepad4，不能作为原生记事本等待能力的验证证据；不得只因使用进程等待 API 就宣称该行为已验收。
- Windows 自然排序细节可能随系统版本变化，采用系统行为已获用户确认。[Microsoft StrCmpLogicalW 文档](https://learn.microsoft.com/en-us/windows/win32/api/shlwapi/nf-shlwapi-strcmplogicalw)
