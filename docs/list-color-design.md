# List 名称着色设计

状态：2026-10-10 用户确认完整方案，包括颜色控制、回退行为和验收范围；已实施，当前行为见[行为契约](spec.md)。

## 问题与目标

`list` 的名称与备注使用相同文字样式，用户扫描列表时不易区分两者。通过增强名称的视觉层次改善查阅体验，沿用现有布局。

## 已确认的决定

2026-10-10，用户确认：

- 名称着色，备注保留终端默认颜色；不增加分隔符，沿用现有排版。
- 默认自动判断终端，仅在支持颜色的终端启用；管道和重定向保持纯文本，并尊重非空 `NO_COLOR`。
- 统一覆盖默认双栏、`--long` 和 `--tree` 三种 `list` 文本模式，包括递归列表。
- JSON、`get` 和帮助输出保持现有行为。
- 名称统一使用终端标准青色，不加粗。目录末尾的 `\` 同色；孤立记录和辅助目录节点采用同一样式；树连接线保持默认色。
- 提供仅用于 `list`（包括别名 `ls`）的 `--color auto|always|never`，默认为 `auto`。`always` 可覆盖 `NO_COLOR` 并向管道输出颜色；`never` 关闭程序添加的颜色。JSON 不添加颜色。
- 名称与备注继续原样输出，不新增控制字符转义或过滤。程序在每个名称（含目录标记）后恢复默认前景色。

## 完整方案

### 颜色控制

| 情况 | 程序添加的颜色 |
| --- | --- |
| JSON 输出 | 不添加，忽略合法的颜色模式 |
| `--color never` | 不添加 |
| `--color always` | 强制添加，包括管道、重定向及非空 `NO_COLOR` |
| 默认或显式 `--color auto`，非空 `NO_COLOR` | 不添加 |
| `auto`，stdout 非终端 | 不添加 |
| `auto`，终端支持颜色且能启用 VT | 添加 |
| `auto`，终端能力检测或 VT 启用失败 | 不添加，继续纯文本查询 |

- `always` 仍尝试为原生控制台启用 VT，但启用失败不取消用户明确要求的颜色序列；不支持的接收端可能显示原始转义码。`auto` 的能力检测失败不作为查询错误。
- 使用终端标准青色（SGR 36），名称后恢复默认前景色（SGR 39）。不使用粗体、暗化、背景色或主题配置；实际青色色值由终端调色板决定。
- 只包裹名称和目录标记，空格填充、正文、树连接线及错误汇总不添加样式。颜色序列不参与显示宽度计算。
- 继续原样输出数据中的控制字符，因此“无色”仅表示程序不添加颜色序列；不保证正文自身没有终端控制序列。
- 参数值独立输入，例如 `dion list --color never`；不增加短选项，不支持 `--color=never`。无效值、缺少值、重复选项或用于其他操作命令时遵循既有参数错误规则；JSON 下仍校验选项。
- 在 `auto` 禁色、`never` 和 JSON 分支不为此次着色修改控制台输出模式。彩色文本输出如需临时修改控制台模式，结束时恢复原值。

### 验收与实施边界

- 沿用真实 CLI 黑盒测试。捕获默认和显式 `auto` 输出，确认管道下与原纯文本布局逐字一致。
- 通过 `always` 捕获三种模式的颜色序列，覆盖中文宽字符、多行及空备注、目录标记、孤立记录和辅助目录节点。确认名称后恢复前景色，正文、空白、树连接线及错误汇总未被添加样式。
- 验证 `NO_COLOR` 非空与空值、`always` 覆盖、`never` 禁色、JSON 不添加样式、参数错误及 `ls` 别名。
- 控制字符样本验证数据仍原样输出；名称样式不改变采集、排序、递归、错误汇总、退出码或备注文件状态。
- 在真实 Windows 控制台验证自动着色、默认前景恢复、浅色和深色背景下的可读性，以及检测或启用失败时的纯文本回退。管道捕获测试不能替代这项验收。
- 实施时同步更新行为契约、README 和命令帮助，执行 `scripts/check.ps1`，沿用现有单文件交付及体积要求。
- 本次设计不引入分隔符、自动折行、内容截断、颜色主题或控制字符净化。

## 调研事实

- `src/listing.rs` 的 `columns`、`long`、`tree` 集中负责三种文本布局；`src/cli.rs` 在渲染前分流 JSON。宽度基于原始名称的 Unicode 显示宽度，新增样式应在宽度计算后输出。
- 项目支持 Windows 10/11 x64。Rust 标准库 `IsTerminal` 可判断输出是否连接终端，但不能单独证明颜色可用。
- Windows 原生控制台解释 VT 序列需要启用 `ENABLE_VIRTUAL_TERMINAL_PROCESSING` 并确保 `ENABLE_PROCESSED_OUTPUT`；应处理不支持的控制台。
- 当前正文校验仅拒绝 NUL 和控制字符 `04`，允许 ESC；文本渲染原样输出名称与正文。启用 VT 后，数据中的 ESC 也可能被终端解释，新增可见转义会改变现有输出行为。
- 现有真实 CLI 测试捕获 stdout，能验证自动模式下的纯文本输出，但不能替代真实终端的颜色验收。

简单固定颜色是可逆的展示选择，不新增 ADR；没有新增领域概念，不修改领域词汇表。
