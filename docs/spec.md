# Dion 行为契约

本文维护 Dion 当前的外部行为，是功能修改与回归测试的依据。第一版原始需求见 [Issue #1](https://github.com/Myraxion/dion/issues/1)，开发过程见[归档](README.md#历史记录)。术语见[领域词汇表](../GLOSSARY.md)，关键决策理由见 [ADR](adr/)。

## 平台与交付

- 支持 Windows 10/11 x64 的本地文件系统。
- 使用 Rust 实现，允许编译期依赖；交付单个 exe，默认 Release 构建静态链接 MSVC CRT，用户无需额外安装运行时。
- UNC、SMB、WebDAV 和网络映射盘不作兼容性承诺，不属于验收或性能测量范围。现有接口可能接受这些路径，但不保证可用；程序不主动识别或拒绝网络存储。

## 命令形态

```text
dion [--json] get <path>
dion [--json] list [directory] [--long|-l]
dion [--json] set <path> <comment>
dion [--json] set <path> --stdin
dion [--json] set <path> --comment-file <file>
dion [--json] remove <path>
```

## 命令与路径

- `get`、`set`、`remove` 接受一个文件或文件夹路径，操作该条目自身的备注，使用其父目录的备注文件。
- `list` 接受可选目录，省略时使用当前目录；只列出自身备注文件中的记录，不递归。查询实际目录条目以识别类型；目录符号链接和 Junction 自身也归入目录组。
- 列表按目录组、文件组输出，各组采用 Windows 不区分大小写的 `StrCmpLogicalW` 自然升序（如 `file2` 在 `file10` 前），比较相等时按原名称的 UTF-16 序列比较。接受系统排序细节随 Windows 版本变化；不改变名称匹配和重复检测。
- 孤立记录保留并归入文件组。非普通记录名称作为完整名称匹配实际条目，无法对应普通条目时作为孤立记录；不解释名称中的分隔符或点组件，不据此访问其他目录。
- `set` 支持正文参数、`--stdin`、`--comment-file`，每次必须且只能选择一个输入来源。
- 支持本地相对、绝对与 Windows 长路径，包括扩展路径 `\\?\D:\资料\条目`。路径中的 `.`、`..` 按词法处理，不解析最终链接目标。符号链接及目录联接自身的备注使用输入条目所在父目录的备注；`list` 链接目录时读取该目录内部的备注。
- 磁盘根支持 `list`；对根自身执行 `get`、`set` 或 `remove` 报参数错误。
- `--json` 可放在命令之前或路径之后。以 `-` 开头的路径或正文放在 `--` 后；以 `-` 开头的正文文件名使用 `./` 前缀，避免被当作选项。

## 输入与正文

- stdin 和备注文本文件严格使用 UTF-8，接受可选 BOM；这与备注文件必须有 BOM 的规则不同。
- 参数中的字面量反斜杠加 n 不自行解释。实际多行可以从多行参数、stdin 或文本文件输入。
- 禁止设置空字符串、纯空白内容、实际 NUL 或实际控制字符 04；Tab 等正常排版内容保留。
- 不裁剪首尾空白或末尾换行。输入 CRLF、LF、CR 统一为逻辑 LF，保留空行和末尾换行数量。
- 设置要求目标条目存在；查看、列出、删除不要求记录所指目标存在。已有空记录允许读取。

## 备注格式与局部修改

- 只读写带 UTF-8 BOM 的备注文件；无 BOM、其他编码或非法 UTF-8 明确报错，不自动检测代码页或转换编码。
- 不强制 BOM 后必须有空行；物理行终止接受 CRLF、LF、CR，末条记录可以没有终止换行。
- 文件名含空格时使用双引号，名称后第一个空格是分隔符，其后的正文空白保留。
- 多行正文写为一条物理记录：逻辑 LF 编码为字面量反斜杠加 n，反斜杠加倍，并附加 TC UTF-8 扩展标记 04 C3 82。单行正文直接写入，不添加扩展。
- 只有带 TC 标记的记录才解释换行和反斜杠转义；其他反斜杠组合及末尾反斜杠按字面保留。
- 未知程序扩展读取 04 前的普通正文，不解释转义；设置该记录返回 `unknown_extension`；显式删除可以移除整条记录。未知扩展本身不属于坏行。
- 名称匹配与重复检测固定使用 Unicode 小写转换，不依赖目录的大小写设置；仅大小写不同的重复记录视为冲突，不能分别操作此类名称。见 [ADR-0002](adr/0002-case-insensitive-record-names.md)。
- 单条记录最多 4096 个 UTF-8 字节，包含名称、引号、分隔空格、正文、扩展及行终止符。超限报错，不截断。
- 已识别的格式错误导致整次操作失败：不输出正常结果，不修改文件。诊断包含适用的文件、物理行号及原因；物理行号包括文件头空行。
- 仅修改目标记录，其余内容按原字节保留。修改保持原位置和名称拼写、新增追加末尾。列表排序只改变输出，不修改备注文件字节、记录顺序、时间或属性。见 [ADR-0001](adr/0001-preserve-unmodified-bytes.md)。
- 新增或实际修改的记录以 CRLF 结束。若原末条没有终止换行，追加前补必要的 CRLF；补充后原记录也须满足长度上限。
- 完成适用校验后，设置的逻辑正文与已有正文相同则成功且不写文件。未知扩展的设置拒绝规则不因内容相同而绕过。

## 输出与 API 契约

- 默认输出方便人阅读；显式 `--json` 返回稳定机器结果，不根据是否接入管道自动切换格式。
- `get` 文本模式只输出正文，以 LF 表示逻辑换行，不额外追加换行。已有空记录输出零字节但成功。
- `list` 文本模式在目录名称末尾添加反斜杠；默认双栏按本次所有显示名称（含目录标记）的显示宽度计算左栏，中文及常见宽字符参与宽度计算，两栏相隔两个空格。多行正文后续行对齐右栏。
- `list --long`（`-l`）让名称独占一行，正文每行缩进四个空格，包括空行；保留正文空行和末尾换行，再额外添加一个记录间空行。`--long` / `-l` 仅适用于 `list`。
- 两种列表文本模式均显示完整正文和已有空记录，保留正常排版空白，不截断、不按终端宽度主动折行；输出行以 LF 结束。`set` 与 `remove` 文本模式成功时不输出。
- 成功结果写 stdout，错误写 stderr；JSON 模式错误也是 JSON。错误时 stdout 为空，包括未找到记录。
- JSON 使用 UTF-8、无 BOM，输出文档以 LF 结束；正文值本身不附加额外换行。
- JSON `get` 结果含 `name`、`comment`、`extension`；名称保留记录原拼写，扩展状态为 `none`、`tc`、`unknown`。
- JSON `list` 结果是含 `entries` 数组的对象，数组中的每条记录使用相同字段，名称不添加目录标记；无备注文件时数组为空。双栏、单栏和 JSON 使用相同记录顺序；文本排版选项不改变 JSON 内容。
- JSON `set` 与 `remove` 结果含布尔字段 `changed`，表示是否实际发生修改。
- JSON 错误包含 `error` 对象，内部有稳定的 `code` 和供人阅读的 `message`，适用时附带 `file`、`line`。错误代码为 `invalid_encoding`、`invalid_format`、`unknown_extension`、`content_changed`、`io_error`（退出码 1）、`invalid_argument`（退出码 2）、`not_found`（退出码 3）。
- 退出码 0 表示成功，1 表示格式、编码、权限及其他 I/O 操作错误，2 表示参数错误，3 表示 `get` 未找到记录。
- `get` 没有记录或备注文件时 stdout 为空，退出码 3；已有空记录返回 0。无法访问目录是操作错误，不能伪装成没有记录。
- `list` 的备注文件不存在、仅有 BOM 或合法空行时成功返回空列表；已有零字节文件因缺 BOM 报编码错误。`remove` 的记录或备注文件不存在时成功且不修改、不创建文件，JSON 返回 `changed:false`。

JSON 结果示例：

| 操作 | 结果 |
| --- | --- |
| `get` | `{"name":"a.txt","comment":"备注正文","extension":"none"}` |
| `list` | `{"entries":[{"name":"a.txt","comment":"备注正文","extension":"none"}]}` |
| `set/remove` | `{"changed":true}` |
| 格式错误 | `{"error":{"code":"invalid_format","message":"引号未闭合","file":"D:\\data\\descript.ion","line":3}}` |

## 文件生命周期、属性与提交

- 首次成功设置自动创建备注文件，文件头为 EF BB BF 0D 0A，新建文件默认设置隐藏属性。
- 显式删除最后一条实际记录后自动删除整个备注文件，这是保留未修改字节的明确例外。已有空记录和未知扩展记录也计入剩余记录。
- 对原本无记录的文件执行不存在目标的删除不触发清理。
- 修改已有备注文件保留其属性、创建时间和访问权限；实际修改或删除只读备注文件报错，不自动解除只读。读取不受只读属性阻止。
- 不修改被备注文件或文件夹的属性。
- 同目录写完整临时文件后提交：已有文件使用 Windows `ReplaceFileW`，新文件提交拒绝覆盖后来出现的文件。不直接截断原文件，也不在替换失败后回退为原地覆盖。见 [ADR-0003](adr/0003-temporary-file-and-single-writer.md)。
- 格式和输入校验失败不修改文件；提交阶段 I/O 错误可能出现部分完成状态，不能承诺所有失败均保持原文件不变或可完整回滚。
- 按单写者使用；发现占用或内容变化时报错，不自动重试或合并。检测变化不等于完整并发协调。
- 默认不生成常驻备份，也不提供备份选项。成功后清理临时文件；提交失败报告备注文件和临时文件路径，保留仍存在的恢复文件。

## 开发验证与性能

功能回归使用真实 CLI 黑盒集成测试，在隔离目录观察 stdout、stderr、退出码、最终文件字节、存在性及 Windows 属性。统一检查入口为 [scripts/check.ps1](../scripts/check.ps1)，开发规范见 [Rust 实践](rust-practices.md)。

真实 TC 双向验收结果见 [TC 互操作报告](tc-interop.md)。删除最后记录、末条无终止换行、4096 字节计数、非标准转义和名称匹配是 Dion 的产品规则；报告中的 TC 观察只适用于已测版本与用例，不能扩大为 TC 的完整行为保证。

Release exe 体积目标为不超过 5 MiB。本地性能以 100 条和 10,000 条记录测量启动、查询、列出、写入耗时、生命周期峰值提交量和 exe 体积；结果、环境与复现方法见[性能基线](benchmarks.md)。目前未设固定时延门槛，测量结果不构成性能保证。

Windows PowerShell 5.1 的默认文本管道可能在输入到达 Dion 前损坏 Unicode；PowerShell 文本管道会追加行终止符。通过 PowerShell 文本管道输入时，显式设置 UTF-8：

```powershell
$savedOutputEncoding = $OutputEncoding
try {
    $OutputEncoding = [System.Text.UTF8Encoding]::new($false)
    "中文第一行`n第二行" | .\dion.exe set '.\照片 😀.txt' --stdin --json
} finally {
    $OutputEncoding = $savedOutputEncoding
}
```

管道追加的行终止符会保留为备注末尾的逻辑换行。需要精确保留原文本末尾时使用 `--comment-file`，示例见 [README](../README.md#快速上手)。

## 范围外功能

- ANSI/OEM、UTF-16 等编码读写、自动转换，以及接受无 BOM 的备注文件。
- 递归查询、备注搜索、批量导入导出、自动清理孤立记录和坏文件修复。
- 文件复制、移动、重命名及对应的备注同步。
- NTFS 备注转换、文件系统监控、后台服务、图形界面或交互式编辑器。
- 常驻备份、多进程或跨机器并发协调、自动重试或合并，以及任意断网或断电下的事务保证。
- 分别处理仅名称大小写不同的两个文件，Windows 10/11 x64 之外的平台与架构，解读或改写未知程序扩展。
