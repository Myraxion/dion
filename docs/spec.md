# Dion 行为契约

本文维护 Dion 当前的外部行为，是功能修改与回归测试的依据。第一版原始需求见 [Issue #1](https://github.com/Myraxion/dion/issues/1)，开发过程见[归档](README.md#历史记录)。术语见[领域词汇表](../GLOSSARY.md)，关键决策理由见 [ADR](adr/)。

## 平台与交付

- 支持 Windows 10/11 x64 的本地文件系统。
- 使用 Rust 实现，允许编译期依赖；交付单个 exe，默认 Release 构建静态链接 MSVC CRT，用户无需额外安装运行时。
- UNC、SMB、WebDAV 和网络映射盘不作兼容性承诺，不属于验收或性能测量范围。现有接口可能接受这些路径，但不保证可用；程序不主动识别或拒绝网络存储。

## 命令形态

```text
dion [--json|-j] get <path>
dion [--json|-j] list [directory] [--long|-l|--tree|-t] [--recursive|-r] [--color auto|always|never]
dion [--json|-j] set <path> <comment>
dion [--json|-j] set <path> --stdin|-i
dion [--json|-j] set <path> --comment-file|-f <file>
dion [--json|-j] set <path> --edit|-e
dion [--json|-j] remove <path>
dion [--json|-j] --help | -h | help [command]
dion [--json|-j] <command> --help | -h
```

- 命令别名：`view`、`cat` 对应 `get`；`ls` 对应 `list`；`rm`、`unset`、`del` 对应 `remove`。`set` 保留原名，无额外别名。别名与完整命令的操作、选项范围、输出及退出码一致。
- 短选项与长选项等价：`--json/-j`、`--help/-h`、`--long/-l`、`--recursive/-r`、`--tree/-t`、`--stdin/-i`、`--comment-file/-f`、`--edit/-e`。`--color` 没有短选项。后文长选项的规则同样适用于对应短选项。
- 命令及选项区分大小写，只接受明确指定的写法，不识别任意前缀。选项须按独立参数输入，不支持短选项连写、选项与值紧连或等号传值；`-f` 的文件名放在下一个参数中。
- 重复选项（包括长短同义组合）报 `invalid_argument`、退出码 2；正文来源互斥、列表模式互斥、命令范围和 `--` 分隔规则保持一致。

## 命令帮助

- 总览入口为 `dion --help`、`dion -h`、`dion help`；四个操作命令均支持 `dion <command> --help`、`dion <command> -h`、`dion help <command>`，不要求操作所需的路径或正文。
- 命令别名支持相同的帮助入口，输出对应完整命令的同一份帮助；总览及有别名的子命令帮助列出全部别名。
- 帮助按当前语言显示，命令、参数及环境变量名称保留英文；总览和子命令帮助仅包含用途、用法、参数及关键默认行为，不包含示例和实现细节。语言选择规则见下文。
- 帮助写 stdout，退出码 0，stderr 为空；带 `--json` 时仍为文本，不包装 JSON。帮助不执行备注读取、列表遍历、修改、正文输入读取或编辑器启动。
- 沿用选项解析和 `--` 分隔规则；`--` 后的 `--help`、`-h` 是普通路径或正文。未知帮助主题或 `help` 的多余位置参数报 `invalid_argument`（退出码 2）；未知/重复选项、互斥列表模式或输入来源仍在参数解析时报错。

## 程序语言

- Dion 的程序文案支持英文和简体中文，帮助、参数错误、操作错误及列表错误汇总均按所选语言显示。用户备注、文件名和 `descript.ion` 内容保持原样。
- `--lang <en|zh-CN|auto>` 是全局长选项，可放在命令和路径前后；接受值不区分大小写，必须与选项分开输入。不支持短选项或等号传值。
- 语言选择顺序为 `--lang`、`DION_LANG`、Windows 当前用户界面语言。未指定时跟随用户界面语言。`auto` 直接使用用户界面语言并忽略 `DION_LANG`。
- 系统简体中文标识映射为 `zh-CN`，包括中国大陆、新加坡及简体中文中性标识；繁体中文、其他语言和检测失败均使用英文。
- 无效、空的 `DION_LANG` 按未设置处理。无效、缺值或重复的 `--lang` 报 `invalid_argument`，退出码为 2；首个真实出现的 `--lang` 的有效值控制整次调用中的文案，包括更早出现的参数错误。无效或缺值时按环境变量与系统语言确定诊断语言。
- 识别 `--lang` 时遵循现有参数值和分隔符规则。由 `--color`、`--comment-file/-f` 消耗的值，以及 `--` 后的字面内容不作为语言选项。
- 文本错误保留稳定错误代码、适用的路径和物理行号；系统错误原文保留，即使与所选语言不同。列表错误区标题随语言变化。
- JSON 错误的 `message` 随语言变化；字段名、错误代码及退出码稳定。脚本按 `code` 判断错误。帮助即使伴随 `--json` 也继续输出所选语言的文本。

## 命令与路径

- `get`、`set`、`remove` 接受一个文件或文件夹路径，操作该条目自身的备注，使用其父目录的备注文件。
- `list` 接受可选目录，省略时使用当前目录；默认只列出自身备注文件中的记录。`--recursive`（`-r`）开启递归，可与双栏、单栏及 JSON 组合，仅适用于 `list`。查询实际目录条目以识别类型；目录符号链接和 Junction 自身也归入目录组。
- 列表按目录组、文件组输出，各组采用 Windows 不区分大小写的 `StrCmpLogicalW` 自然升序（如 `file2` 在 `file10` 前），比较相等时按原名称的 UTF-16 序列比较。接受系统排序细节随 Windows 版本变化；不改变名称匹配和重复检测。
- 孤立记录保留并归入文件组。非普通记录名称作为完整名称匹配实际条目，无法对应普通条目时作为孤立记录；不解释名称中的分隔符或点组件，不据此访问其他目录。
- 普通递归每个目录先输出自身全部已排序记录，再按实际子目录名称自然升序逐个深度优先递归，不将结果重新按完整路径排序。没有备注文件的中间目录仍遍历子目录。
- `--tree` 仅适用于 `list`，自动开启递归，不显示起始目录根节点；与显式 `--recursive`（`-r`）组合不改变结果。`--tree` 与 `--long`（`-l`）互斥，即使带 `--json` 也返回参数错误。
- `--color` 仅适用于 `list`，值为 `auto`、`always` 或 `never`，默认 `auto`。名称着色只作用于文本输出，不改变布局、顺序、名称宽度或备注内容。`auto` 仅在 stdout 为终端、Windows VT 模式启用成功且 `NO_COLOR` 未设置为非空值时着色；检测或启用失败回退纯文本。`always` 强制输出颜色序列，包括管道，并覆盖 `NO_COLOR`；`never` 不添加颜色序列。`--color` 可与 JSON 组合并继续校验参数，但 JSON 从不添加颜色。
- 树仅显示备注记录及连接它们所需的辅助目录节点，无备注且没有相关后代的目录不显示。目录自身备注与展开节点合并，保留记录名称拼写，先显示自身完整正文，再紧跟子节点。每层兄弟节点按目录优先及上述自然排序展开，辅助节点也参与目录优先；层级来自实际遍历的目录，不拆分非普通记录名称。
- 递归途中不进入目录符号链接或 Junction，其自身备注仍可列出并标识为目录；显式起始目录为链接或 Junction 时读取内部。其他目录重解析点不额外排除。
- 递归名称使用相对于起始目录的路径和 Windows 分隔符，起始目录内名称不加点前缀，记录名称保留既有拼写。非普通名称作为文本追加在所属目录前缀之后，不拆分、规范化或构造层级。
- `list` 默认跳过错误并继续查询：坏 UTF-8、格式错误、超长记录只跳过对应物理行；大小写重复名称保留首条有效记录，后续重复行报错。缺少 BOM（包括零字节文件）跳过整个备注文件，不猜测或转换编码。
- 备注文件无法读取时汇总错误，递归仍访问该目录的子目录。目录枚举、目录项读取或类型查询失败时，跳过该目录的全部内容并继续其他目录；无法表示为 UTF-8 的待递归目录名称同样使所属目录跳过。起始目录不存在、不是目录或无法完成枚举时直接失败，stdout 为空。
- 跳过的错误按目录遍历顺序汇总，同一备注文件内按物理行顺序排列，保留适用的文件、物理行号和原因。错误不改变正常记录的排序、链接边界及树辅助节点规则。
- `set` 支持正文参数、`--stdin`、`--comment-file`、`--edit`，每次必须且只能选择一个输入来源。
- 支持本地相对、绝对与 Windows 长路径，包括扩展路径 `\\?\D:\资料\条目`。路径中的 `.`、`..` 按词法处理，不解析最终链接目标。符号链接及目录联接自身的备注使用输入条目所在父目录的备注；`list` 链接目录时读取该目录内部的备注。
- 磁盘根支持 `list`；对根自身执行 `get`、`set` 或 `remove` 报参数错误。
- `--json` 可放在命令之前或路径之后。以 `-` 开头的路径或正文放在 `--` 后；以 `-` 开头的正文文件名使用 `./` 前缀，避免被当作选项。

## 输入与正文

- `set` 的正文参数、`--stdin`、`--comment-file`、`--edit` 四种输入来源互斥；输入来源选项仅用于 `set`。
- stdin、正文文件和编辑临时文本严格使用 UTF-8，接受可选 BOM；这与备注文件必须有 BOM 的规则不同。
- 参数中的字面量反斜杠加 n 不自行解释。实际多行可以从多行参数、stdin 或文本文件输入。
- 正文参数、stdin 和正文文件禁止空字符串；所有来源禁止纯空白内容、实际 NUL 或实际控制字符 04。Tab 等正常排版内容保留；编辑后的空字符串按下述删除规则处理。
- 不裁剪首尾空白或末尾换行。输入 CRLF、LF、CR 统一为逻辑 LF，保留空行和末尾换行数量。
- 设置非空正文要求目标条目存在；查看、列出、删除不要求记录所指目标存在。已有空记录允许读取。

## 外部编辑

- `set --edit` 在打开编辑器前解析备注文件，捕获原始字节及存在性快照。临时 UTF-8 文本预填匹配记录的逻辑正文（不含程序扩展），无记录则为空；名称匹配使用下述 Windows 原生比较规则。
- 编辑器按非空 `VISUAL`、非空 `EDITOR`、`notepad.exe` 顺序选择。配置值作为 Windows 命令行，带空格的程序路径使用双引号，后续参数保持命令行引用；末尾追加编辑文本路径。例如 `VISUAL='"C:\Program Files\editor\editor.exe" --wait'`。程序等待编辑器进程正常退出后读取文本；需要等待参数的编辑器由配置提供，例如 `code --wait`。
- 编辑器启动或非零退出不提交备注。编辑器正常退出后重新读取备注文件，与编辑前快照比较；字节改变、原文件出现或消失报 `content_changed`，包括编辑正文未变化的情况。不重新捕获基线、不覆盖或合并其他修改。
- 严格读取 UTF-8、去除可选 BOM并统一 CRLF/CR 为逻辑 LF，不裁剪正文。空字符串先按现有删除规则处理：已有空记录原样关闭也删除，最后记录删除备注文件；无记录成功且不写入、不创建文件。孤立记录和未知扩展记录可以清空删除。
- 非空正文先校验输入、目标存在性和未知扩展，再比较逻辑正文。纯空格、Tab 或换行仍是输入错误；孤立记录非空编辑报目标访问错误；未知扩展非空编辑（包括原样关闭）报 `unknown_extension`。校验通过且正文相等则成功且不写入，保留原字节、时间和属性。
- 文本成功仍静默，JSON 仍只返回 `changed` 布尔值。成功清理编辑文本；启动、编辑、输入校验或保存失败保留已创建的文本，在 stderr 报告路径。JSON 错误的 `message` 携带恢复路径，不增加字段；错误代码和退出码沿用既有契约。
- 实际设置及清空删除继续遵循只读属性、局部字节保留和 Windows 提交规则。保存阶段仍可能部分完成；保留编辑文本不意味着提交失败均能回滚。编辑前后检查只用于发现冲突，检查到提交之间仍有竞态，继续限定单写者使用。

## 备注格式与局部修改

- 只读写带 UTF-8 BOM 的备注文件；无 BOM、其他编码或非法 UTF-8 明确报错，不自动检测代码页或转换编码。`list` 按上述跳过规则保留可读取的记录。
- 不强制 BOM 后必须有空行；物理行终止接受 CRLF、LF、CR，末条记录可以没有终止换行。
- 文件名含空格时使用双引号，名称后第一个空格是分隔符，其后的正文空白保留。
- 多行正文写为一条物理记录：逻辑 LF 编码为字面量反斜杠加 n，反斜杠加倍，并附加 TC UTF-8 扩展标记 04 C3 82。单行正文直接写入，不添加扩展。
- 只有带 TC 标记的记录才解释换行和反斜杠转义；其他反斜杠组合及末尾反斜杠按字面保留。
- 未知程序扩展读取 04 前的普通正文，不解释转义；设置该记录返回 `unknown_extension`；显式删除可以移除整条记录。未知扩展本身不属于坏行。
- 名称匹配、重复检测、列表目录识别及树节点合并统一使用 Windows `CompareStringOrdinal(..., TRUE)`，按系统大写表固定不区分大小写，不依赖目录的大小写设置或用户语言设置，不进行 Unicode 规范化。按该比较器相等的重复记录视为冲突，不能分别操作；名称保留原拼写，列表自然排序另按上述展示规则执行。接受不同于 Rust Unicode 小写转换的名称相等关系，不承诺完全复现所有文件系统或 Total Commander 的匹配规则。见 [ADR-0002](adr/0002-case-insensitive-record-names.md) 和[名称比较设计](windows-name-comparison-design.md)。
- 单条记录最多 4096 个 UTF-8 字节，包含名称、引号、分隔空格、正文、扩展及行终止符。超限报错，不截断。
- `get`、`set`、`remove` 遇已识别的编码或格式错误导致整次操作失败：不输出正常结果，不修改文件。`list` 跳过坏记录并汇总错误。诊断包含适用的文件、物理行号及原因；物理行号包括文件头空行。
- 仅修改目标记录，其余内容按原字节保留。修改保持原位置和名称拼写、新增追加末尾。列表排序只改变输出，不修改备注文件字节、记录顺序、时间或属性。见 [ADR-0001](adr/0001-preserve-unmodified-bytes.md)。
- 新增或实际修改的记录以 CRLF 结束。若原末条没有终止换行，追加前补必要的 CRLF；补充后原记录也须满足长度上限。
- 完成适用校验后，设置的逻辑正文与已有正文相同则成功且不写文件。未知扩展的设置拒绝规则不因内容相同而绕过。

## 输出与 API 契约

- 默认输出方便人阅读；显式 `--json` 返回稳定机器结果，不根据是否接入管道自动切换格式。
- `get` 文本模式只输出正文，以 LF 表示逻辑换行，不额外追加换行。已有空记录输出零字节但成功。
- `list` 文本模式在目录名称末尾添加反斜杠；默认双栏按本次所有显示名称（含目录标记）的显示宽度计算左栏，中文及常见宽字符参与宽度计算，两栏相隔两个空格。多行正文后续行对齐右栏。
- `list --long`（`-l`）让名称独占一行，正文每行缩进四个空格，包括空行；保留正文空行和末尾换行，再额外添加一个记录间空行。`--long` / `-l` 仅适用于 `list`。
- `list --tree` 使用 `├──`、`└──` 和 `│` 连接节点，名称后两个空格接正文，多行正文后续行对齐该节点正文起点，按名称显示宽度计算；不设全树统一右栏，不额外添加记录间空行。辅助目录节点只显示名称和目录标记，不伪造备注记录。
- 默认、单栏和树状列表将名称及目录标记显示为终端标准青色（SGR 36），名称后恢复默认前景色（SGR 39）；树状列表的 `├──`、`└──`、`│` 连接符也显示为相同青色，缩进空格、备注和错误汇总不添加样式。目录标记、孤立记录及辅助目录节点采用同样颜色，不加粗。颜色控制序列不参与显示宽度计算。名称和备注原有内容（包括控制字符）继续原样输出。`--color never`、JSON 及自动回退的纯文本输出没有程序添加的颜色序列。
- 三种列表文本模式均显示完整正文和已有空记录，保留正常排版空白，不截断、不按终端宽度主动折行；输出行以 LF 结束。`set` 与 `remove` 文本模式成功时不输出。
- 成功结果写 stdout；终止错误写 stderr，JSON 模式终止错误也是 JSON，stdout 为空，包括未找到记录。`list` 已跳过的错误与正常列表共同写 stdout，不重复写 stderr；输出写入失败是终止错误，可能已输出部分字节。
- `list` 三种文本模式在正常列表之后追加错误区，简体中文标题为 `错误（N）：`，英文标题为 `Errors (N):`，每条错误独占一行，包含代码、原因、路径及适用的物理行号。有正常列表时在错误区之前添加一个空行；没有错误时不追加任何内容。
- JSON 使用 UTF-8、无 BOM，输出文档以 LF 结束；正文值本身不附加额外换行。
- JSON `get` 结果含 `name`、`comment`、`extension`；名称保留记录原拼写，扩展状态为 `none`、`tc`、`unknown`。
- JSON `list` 结果是含 `entries` 和 `errors` 数组的对象。每条备注记录使用相同字段，名称不添加目录标记；查询范围内无有效记录时 `entries` 为空。每条错误使用既有 `code`、`message` 及适用的 `file`、`line` 字段，无错误时 `errors:[]`。双栏、单栏和 JSON 使用相同直接或普通递归记录顺序；文本排版选项不改变 JSON 内容。递归不增加辅助目录节点；双栏宽度按本次全部相对名称及目录标记计算。
- 树 JSON 与同一起始目录的普通递归 JSON 完全相同，沿用普通递归顺序及字段，不包含辅助目录节点或文本目录标记。树模式复用普通递归的链接边界、显式链接起始目录及错误跳过规则。
- JSON `set` 与 `remove` 结果含布尔字段 `changed`，表示是否实际发生修改。
- JSON 错误包含 `error` 对象，内部有稳定的 `code` 和供人阅读的 `message`，适用时附带 `file`、`line`。错误代码为 `invalid_encoding`、`invalid_format`、`unknown_extension`、`content_changed`、`io_error`（退出码 1）、`invalid_argument`（退出码 2）、`not_found`（退出码 3）。
- 退出码 0 表示成功，1 表示格式、编码、权限及其他 I/O 操作错误（包括 `list` 已输出部分或空列表并汇总了跳过的错误），2 表示参数错误，3 表示 `get` 未找到记录。
- `get` 没有记录或备注文件时 stdout 为空，退出码 3；已有空记录返回 0。无法访问目录是操作错误，不能伪装成没有记录。
- 非递归 `list` 的备注文件不存在、仅有 BOM 或合法空行时成功返回空列表；递归仍继续读取子目录。已有零字节文件因缺 BOM 报编码错误。`remove` 的记录或备注文件不存在时成功且不修改、不创建文件，JSON 返回 `changed:false`。

JSON 结果示例：

| 操作 | 结果 |
| --- | --- |
| `get` | `{"name":"a.txt","comment":"备注正文","extension":"none"}` |
| `list` | `{"entries":[{"name":"a.txt","comment":"备注正文","extension":"none"}],"errors":[]}` |
| `list` 跳过坏行 | `{"entries":[],"errors":[{"code":"invalid_format","message":"引号未闭合","file":"D:\\data\\descript.ion","line":3}]}` |
| `set/remove` | `{"changed":true}` |
| 格式错误 | `{"error":{"code":"invalid_format","message":"引号未闭合","file":"D:\\data\\descript.ion","line":3}}` |

## 文件生命周期、属性与提交

- 首次成功设置自动创建备注文件，文件头为 EF BB BF 0D 0A，新建文件默认设置隐藏属性。
- 显式删除最后一条实际记录后自动删除整个备注文件，这是保留未修改字节的明确例外。已有空记录和未知扩展记录也计入剩余记录。
- 对原本无记录的文件执行不存在目标的删除不触发清理。
- 修改已有备注文件保留其属性、创建时间和访问权限；实际修改或删除只读备注文件报错，不自动解除只读。读取不受只读属性阻止。
- 不修改被备注文件或文件夹的属性。
- 同目录写完整临时文件后提交：已有文件使用 Windows `ReplaceFileW`，新文件提交拒绝覆盖后来出现的文件。不直接截断原文件，也不在替换失败后回退为原地覆盖。见 [ADR-0003](adr/0003-temporary-file-and-single-writer.md)。
- 格式和输入校验失败不修改文件；提交阶段 I/O 错误可能出现部分完成状态，不能承诺所有失败均保持原文件不变或可完整回滚。
- 按单写者使用；发现占用或内容变化时报错，不自动重试或合并。检测变化不等于完整并发协调。
- 默认不生成常驻备份，也不提供备份选项。成功后清理临时文件；提交失败报告备注文件和临时文件路径，保留仍存在的恢复文件。

## 开发验证与性能

功能回归使用真实 CLI 黑盒集成测试，在隔离目录观察 stdout、stderr、退出码、最终文件字节、存在性及 Windows 属性。统一检查入口为 [scripts/check.ps1](../scripts/check.ps1)，开发规范见 [Rust 实践](rust-practices.md)。

外部编辑使用受控进程测试预填、等待、配置顺序、引号及参数、输入校验、清空、no-op、冲突检测、恢复文本和成功清理。2026-10-09，用户手动验证默认原生 Windows 记事本的等待行为并确认通过，补齐 [Issue #16](https://github.com/Myraxion/dion/issues/16) 的人工验收。该结论来自用户实测确认，受控编辑器、被重定向的记事本或进程等待 API 本身均不能替代此项证据。

真实 TC 双向验收结果见 [TC 互操作报告](tc-interop.md)。删除最后记录、末条无终止换行、4096 字节计数、非标准转义和名称匹配是 Dion 的产品规则；报告中的 TC 观察只适用于已测版本与用例，不能扩大为 TC 的完整行为保证。

Release exe 体积目标为不超过 5 MiB。本地性能以 100 条和 10,000 条记录测量启动、查询、列出、写入耗时、生命周期峰值提交量和 exe 体积；结果、环境与复现方法见[性能基线](benchmarks.md)。目前未设固定时延门槛，测量结果不构成性能保证。

Windows PowerShell 5.1 的默认文本管道可能在输入到达 Dion 前损坏 Unicode；PowerShell 文本管道会追加行终止符。通过 PowerShell 文本管道输入时，显式设置 UTF-8：

```powershell
$savedOutputEncoding = $OutputEncoding
try {
    $OutputEncoding = [System.Text.UTF8Encoding]::new($false)
    "中文第一行`n第二行" | .\dion.exe set '.\照片 😀.txt' --stdin --json
} finally {
    $OutputEncoding = $savedOutputEncoding
}
```

管道追加的行终止符会保留为备注末尾的逻辑换行。需要精确保留原文本末尾时使用 `--comment-file`，示例见 [README](../README.md#快速上手)。
