# Dion 第一版：Windows 原生 descript.ion 备注 CLI

## Problem Statement

Total Commander 用户将文件与文件夹的备注保存在所在目录的 `descript.ion` 中，但需要一个轻量的命令行入口来查看、设置和删除备注，并让 Agent 与脚本可靠地判断结果。直接编辑备注文件容易破坏编码、多行转义、程序扩展或其他记录；交互界面又不适合作为脚本接口。

用户希望在 Windows 10/11 x64 上，包括 UNC 网络共享路径，通过单个无需额外运行时的 exe 完成日常备注操作。第一版优先支持 TC 的带 BOM UTF-8 格式，行为明确、修改范围可控，并能在真实工作负载下验证性能。

## Solution

提供 Rust 编写的 Windows 原生 CLI，包含 `get`、`list`、`set`、`remove` 四个命令。默认输出方便用户阅读，显式 `--json` 提供稳定的机器接口；设置备注支持正文参数、stdin 和 UTF-8 文本文件三种互斥输入来源。

工具严格校验备注文件，局部修改目标记录并保留其他内容的原始字节。空白输入不会清空已有备注；只有显式删除会移除记录，删除最后一条记录后自动删除备注文件。写入先生成同目录临时文件，再提交替换；第一版按单写者使用，支持 UNC 访问，但不提供跨机器并发协调保证。

## User Stories

1. 作为 Windows 用户，我希望只分发一个 exe 且无需额外安装运行时，以便直接在本机和脚本环境中使用。
2. 作为用户，我希望在 Windows 10/11 x64 上使用工具，以便覆盖主要桌面环境。
3. 作为网络共享用户，我希望通过 UNC 路径查看和编辑备注，以便处理共享目录中的文件。
4. 作为用户，我希望查看指定文件的备注，以便无需打开 Total Commander 即可了解文件用途。
5. 作为用户，我希望查看文件夹自身的备注，以便区分文件夹说明与其内部条目的说明。
6. 作为用户，我希望列出指定目录的备注记录，以便一次查看该目录已有的备注。
7. 作为用户，我希望省略列出命令的目录时使用当前目录，以便快速完成日常查询。
8. 作为用户，我希望为已有文件或文件夹新增备注，以便补充文字说明。
9. 作为用户，我希望覆盖已有备注，以便更新说明而不重建其他记录。
10. 作为用户，我希望显式删除备注，以便有意移除不再需要的说明。
11. 作为脚本作者，我希望设置空字符串或纯空白内容时报错，以便变量为空时不会意外清空已有备注。
12. 作为用户，我希望读取已有空记录，以便兼容其他程序已经生成的内容。
13. 作为用户，我希望保留备注的缩进、首尾空白、连续空行和末尾换行数量，以便保留排版意图。
14. 作为用户，我希望正确读取和设置多行备注，以便与 TC 的多行格式兼容。
15. 作为用户，我希望正文中的反斜杠和字面量反斜杠加 n 不被误当作换行，以便正确保存路径及示例文本。
16. 作为用户，我希望中文、其他 Unicode 字符和 Emoji 能正确读写，以便使用国际化名称与备注。
17. 作为用户，我希望包含空格的文件名得到正确处理，以便操作常见的长文件名。
18. 作为用户，我希望通过正文参数直接设置短备注，以便减少交互步骤。
19. 作为脚本作者，我希望通过 stdin 提供备注，以便连接其他命令的输出。
20. 作为用户，我希望从 UTF-8 文本文件读取备注，以便提供较长或多行内容。
21. 作为脚本作者，我希望三个输入来源互斥，以便输入来源冲突时得到明确错误。
22. 作为用户，我希望没有 BOM 或不是 UTF-8 的备注文件被明确拒绝，以便避免隐式转换损坏原内容。
23. 作为用户，我希望未闭合引号、超长行、非法 UTF-8 或名称冲突导致整次操作失败，以便错误文件不会被悄悄改写。
24. 作为用户，我希望格式错误指出文件、物理行号和原因，以便定位需要修复的内容。
25. 作为用户，我希望修改一条记录时保留其余内容的原始字节，以便保留其他记录的顺序、空白、换行和程序扩展。
26. 作为用户，我希望查看和删除孤立记录，以便处理文件已经不存在但备注仍保留的情况。
27. 作为脚本作者，我希望设置备注要求目标条目存在，以便拼错文件名时不会创建错误记录。
28. 作为用户，我希望名称匹配固定不区分大小写，以便获得稳定的普通 Windows 使用体验。
29. 作为用户，我希望仅大小写不同的重复记录被视为冲突，以便不发生不明确的覆盖。
30. 作为用户，我希望读取带未知程序扩展记录的普通正文，以便仍能获取基本说明。
31. 作为用户，我希望设置带未知程序扩展的记录时报错，以便不破坏无法解释的附加信息。
32. 作为用户，我希望显式删除允许移除带未知扩展的整条记录，以便有意清理该备注。
33. 作为脚本作者，我希望通过 JSON 获取记录及其扩展解释状态，以便可靠地判断内容和可修改性。
34. 作为脚本作者，我希望成功结果和错误分别写到 stdout 与 stderr，以便分别收集结果和诊断。
35. 作为脚本作者，我希望使用稳定退出码区分成功、参数错误、操作错误和没有记录，以便进行条件分支。
36. 作为脚本作者，我希望重复删除不存在的记录仍成功，以便实现幂等操作。
37. 作为脚本作者，我希望列出没有备注文件的目录得到空列表，以便无需额外判断备注文件是否存在。
38. 作为用户，我希望设置相同逻辑正文时不写文件，以便避免不必要的 I/O 和时间戳变化。
39. 作为脚本作者，我希望 JSON 写操作结果报告是否实际修改，以便识别无需改写的操作。
40. 作为用户，我希望新增记录追加到末尾、修改保留原位置，以便原有排列保持稳定。
41. 作为用户，我希望首次设置自动创建备注文件，以便不必手工准备格式头。
42. 作为用户，我希望删除最后一条实际记录后自动删除备注文件，以便不留下空的备注文件。
43. 作为用户，我希望新建备注文件默认隐藏，并保留已有文件的属性、创建时间和访问权限，以便符合目录中的既有使用方式。
44. 作为用户，我希望对只读备注文件的修改或删除直接报错，以便不被自动解除保护。
45. 作为用户，我希望完整写出临时文件后才提交替换，以便避免直接截断原备注文件。
46. 作为用户，我希望检测到占用或内容变化时明确报错，以便不自动合并或重试不确定的写入。
47. 作为用户，我希望正常成功后清理临时文件、失败时报告恢复所需文件的位置，以便处理失败而不积累常驻备份。
48. 作为用户，我希望支持相对、绝对和 Windows 长路径，以便操作真实目录结构。
49. 作为用户，我希望操作链接条目自身的备注而不是其目标的备注，以便名称与所在目录关系保持一致。
50. 作为用户，我希望根目录可列出其子项备注，而根自身无法备注时得到参数错误，以便避免误定位备注文件。
51. 作为用户，我希望过长备注报错而不被截断，以便不会无声丢失内容。
52. 作为用户，我希望实际换行类型得到统一处理，以便来自不同文本来源的备注具有一致逻辑内容。
53. 作为脚本作者，我希望读取正文时不额外追加换行，以便正文不会因输出方式而改变。
54. 作为用户，我希望先取得 Release 性能基线，再确定时延门槛，以便性能目标建立在真实测量上。
55. 作为用户，我希望发布 exe 暂以不超过 5 MiB 为目标，以便保持轻量分发。
56. 作为用户，我希望本地与 UNC 测试结果分别报告，以便知道真实共享场景是否已经验证。

## Implementation Decisions

### 产品与模块职责

- 使用 Rust，面向 Windows 10/11 x64；允许编译期依赖，交付无需额外运行时的单个 exe。
- 从外部行为组织 CLI 与输出、备注格式处理、Windows 文件提交三个职责。职责边界不要求独立 crate 或额外抽象层；保持 KISS，具体内部拆分由实现决定。
- 尊重已记录的三个 ADR：保留未修改原始字节、固定不区分大小写匹配、同目录临时文件提交且限定单写者。

### 命令与路径

- `get`、`set`、`remove` 接受一个文件或文件夹路径，操作该条目自身的备注，使用其父目录的备注文件。
- `list` 接受可选目录，省略时使用当前目录；只读取备注记录，不检查目标是否存在、不枚举目录、不递归。
- `set` 支持正文参数、`--stdin`、`--comment-file`，每次必须且只能选择一个输入来源。
- 支持相对、绝对、UNC 与 Windows 长路径。符号链接及目录联接使用输入条目所在父目录的备注，不转而操作链接目标的备注。
- 磁盘根和 UNC 共享根支持 `list`；对根自身执行 `get`、`set` 或 `remove` 报参数错误。

### 输入与正文

- stdin 和备注文本文件严格使用 UTF-8，接受可选 BOM；这与备注文件必须有 BOM 的规则不同。
- 参数中的字面量反斜杠加 n 不自行解释。实际多行可以从多行参数、stdin 或文本文件输入。
- 禁止设置空字符串、纯空白内容、实际 NUL 或实际控制字符 04；Tab 等正常排版内容保留。
- 不裁剪首尾空白或末尾换行。输入 CRLF、LF、CR 统一为逻辑 LF，保留空行和末尾换行数量。
- 设置要求目标条目存在；查看、列出、删除不要求记录所指目标存在。已有空记录允许读取。

### 备注格式与局部修改

- 只读写带 UTF-8 BOM 的备注文件；无 BOM、其他编码或非法 UTF-8 明确报错，不自动检测代码页或转换编码。
- 不强制 BOM 后必须有空行；物理行终止接受 CRLF、LF、CR，末条记录可以没有终止换行。
- 文件名含空格时使用双引号，名称与正文间使用一个空格。
- 多行正文写为一条物理记录：逻辑 LF 编码为字面量反斜杠加 n，反斜杠加倍，并附加 TC UTF-8 扩展标记 04 C3 82。
- 只有带 TC 标记的记录才解释换行和反斜杠转义；其他反斜杠组合按字面保留。
- 未知程序扩展读取 04 前的普通正文；设置该记录报“未知扩展，无法修改”；显式删除可以移除整条记录。未知扩展本身不属于坏行。
- 名称匹配固定不区分大小写，仅大小写不同的重复记录视为冲突；第一版不分别处理此类名称在区分大小写目录中的两个文件。
- 单条记录最多 4096 个 UTF-8 字节，包含名称、引号、分隔空格、正文、扩展及行终止符。超限报错，不截断。
- 已识别的格式错误导致整次操作失败：不输出正常结果，不修改文件。诊断包含适用的文件、物理行号及原因；物理行号包括文件头空行。
- 仅修改目标记录，其余内容按原字节保留。修改保持原位置、新增追加末尾、列出保持原始顺序，不自动排序。
- 新增或实际修改的记录以 CRLF 结束。若原末条没有终止换行，追加前补必要的 CRLF；补充后原记录也须满足长度上限。
- 完成适用校验后，设置的逻辑正文与已有正文相同则成功且不写文件。未知扩展的设置拒绝规则不因内容相同而绕过。

### 输出与 API 契约

- 默认输出方便人阅读；显式 `--json` 返回稳定机器结果，不根据是否接入管道自动切换格式。
- `get` 文本模式只输出正文，以 LF 表示逻辑换行，不额外追加换行。已有空记录输出零字节但成功。
- `list` 文本模式输出名称和完整备注的可读列表；`set` 与 `remove` 文本模式成功时不输出。
- 成功结果写 stdout，错误写 stderr；JSON 模式错误也是 JSON。错误时 stdout 为空，包括未找到记录。
- JSON 使用 UTF-8、无 BOM，输出文档以 LF 结束；正文值本身不附加额外换行。
- JSON `get` 结果含 `name`、`comment`、`extension`；名称保留记录原拼写，扩展状态为 `none`、`tc`、`unknown`。
- JSON `list` 结果是含 `entries` 数组的对象，数组中的每条记录使用相同字段；无备注文件时数组为空。
- JSON `set` 与 `remove` 结果含布尔字段 `changed`，表示是否实际发生修改。
- JSON 错误是含 `error` 对象的结果，内部有稳定 `code` 和供人阅读的 `message`，适用时附带 `file`、`line`；格式错误代码示例为 `invalid_format`。
- 退出码 0 表示成功，1 表示格式、编码、权限、网络等操作错误，2 表示参数错误，3 表示 `get` 未找到记录。
- `get` 没有记录或备注文件时 stdout 为空，退出码 3；已有空记录返回 0。无法访问目录或共享是操作错误，不能伪装成没有记录。
- `list` 的备注文件不存在时成功返回空列表；`remove` 的记录或备注文件不存在时成功且不修改、不创建文件，JSON 返回 `changed:false`。

### 文件生命周期、属性与提交

- 首次成功设置自动创建备注文件，文件头为 EF BB BF 0D 0A，新建文件默认设置隐藏属性。
- 显式删除最后一条实际记录后自动删除整个备注文件，这是保留未修改字节的明确例外。已有空记录和未知扩展记录也计入剩余记录。
- 对原本无记录的文件执行不存在目标的删除不触发清理。
- 修改已有备注文件保留其属性、创建时间和访问权限；修改或删除只读备注文件报错，不自动解除只读。读取不受只读属性阻止。
- 不修改被备注文件或文件夹的属性。
- 同目录写完整临时文件后提交替换；不直接截断原文件，也不在替换失败后回退为原地覆盖。
- 格式和输入校验失败不修改文件；提交阶段 I/O 错误可能出现部分完成状态，不能承诺所有失败均保持原文件不变或可完整回滚。
- 第一版按单写者使用；发现占用或内容变化时报错，不自动重试或合并。检测变化不等于完整并发协调。
- 默认不生成常驻备份，也不提供备份选项。正常成功后清理临时文件，失败时保留恢复所需文件并报告位置。

### 性能与交付

- 优先冷启动和普通目录操作，采用 100 条及 1 万条记录的本地基准。
- 记录启动、查询、列出、写入耗时，峰值内存及 exe 体积。
- 取得 Release 基线后再确定耗时门槛；exe 体积暂以不超过 5 MiB 为目标。
- UNC 单独测量和报告，不设统一耗时门槛；暂定体积目标和待定耗时门槛不得写成已达成结果。

## Testing Decisions

- **用户已确认测试入口：真实 CLI 进程的黑盒集成测试。** 功能测试在隔离目录启动构建后的程序，观察 stdout、stderr、退出码、最终文件字节、文件是否存在及 Windows 属性。优先一个高层入口，不为测试添加生产专用接口。
- 好的测试验证用户可见行为和不可破坏的文件结果，不验证内部调用次数、函数拆分、数据结构或具体 Windows API 选择。不要求为了职责拆分而建立额外测试边界。
- 通过同一入口覆盖 CLI 输入输出、备注解析与序列化、Windows 文件创建/替换/删除以及属性和权限行为；真实 UNC 环境也运行该入口，性能测量使用同一个 exe。
- 当前仓库只有设计、领域文档、ADR 与样本，没有现有 Rust 实现或测试框架，因此没有可复用的现成代码测试。先复用已有合法与边缘样本，以及五类坏样本的语义，采用可提交或可复现的隔离测试数据，避免依赖开发者本机的被忽略目录。
- 合法样本覆盖 Unicode 名称、空格名称、点文件、无扩展名、文件夹、空记录、仅头文件、连续空行、尾部逻辑换行、反斜杠和较长记录。
- 错误场景覆盖未闭合引号、缺 BOM、非法 UTF-8、超长行、大小写名称冲突、空白输入、保留控制字符和多输入来源冲突。断言错误退出、没有正常 stdout，且备注文件原始字节未变。
- 验证只改目标记录的字节保留、原始顺序、相同内容设置不落盘、孤立记录读取与删除、未知扩展读取/设置拒绝/删除。
- 验证首次创建、删除最后记录、剩余空记录、剩余未知扩展记录、无记录删除幂等和原本空文件不被无效删除请求清理。
- 对序列化后的 4096 字节边界及超过边界的记录进行测试，覆盖 Unicode、文件名、扩展和终止换行的计数；末条无终止换行追加分隔符后仍要验证长度限制。
- 验证正文参数、UTF-8 stdin 和文本文件，以及实际 CRLF/LF/CR 与字面量反斜杠加 n 的区别；不得裁剪缩进或尾部空行。
- 验证默认文本输出、JSON 字段、扩展状态、空记录、缺失记录、stderr 分离与四类退出码；机器错误由稳定代码判断，不依赖文案匹配。
- 在 Windows 验证路径、根目录、符号链接/目录联接、长路径、隐藏属性、创建时间、访问权限及只读错误。链接测试以链接所在目录的备注文件作为可观察结果。
- 在真实共享环境验证 UNC 的读取、创建、替换、删除、属性与访问失败；环境不可用时明确报告未验证，不能将本地目录模拟结果视为 UNC 验证通过。
- 对可复现的占用或内容变化验证拒绝操作与错误报告，不把单写者测试包装成跨机器并发保证。
- 使用 Release 构建记录 100 条和 1 万条场景的性能基线，说明机器、工作负载和测量条件；分别报告本地与 UNC，记录体积和峰值内存。基线建立后再确定耗时阈值。
- 在实现阶段补充 TC 实际读写交叉验证，以检查正文、多行转义及程序扩展兼容性；区分已执行结果与尚未验证的格式推断。

## Out of Scope

- ANSI/OEM、UTF-16 等其他编码的读写或自动转换，以及无 BOM 备注文件的接受。
- 递归查询、备注搜索、批量导入导出、自动清理孤立记录和坏文件修复。
- 文件复制、移动、重命名，以及对应的备注同步维护。
- NTFS 备注转换、文件系统监控、后台服务、图形界面或交互式编辑器流程。
- 常驻备份文件或备份选项。
- 多进程、跨机器同时修改同一备注文件的协调、自动重试或合并，以及任意断网或断电条件下的事务保证。
- 分别处理仅名称大小写不同的两个文件，以及 Windows 10/11 x64 之外的平台与架构。
- 解读或改写未知程序扩展；读取普通正文和显式删除整条记录仍在范围内。
- 未经 Release 基线测量就承诺固定时延，或将所有 UNC 共享设为同一性能门槛。

## Further Notes

- 本规格综合已逐项确认的 28 项设计决定和本次用户确认的 CLI 黑盒测试入口，不重新开启需求访谈。
- 当前尚未实现应用，也未运行应用测试、TC 交叉验证、UNC 验证或性能测量；本规格描述待实现与待验证的结果。
- 以下是已选择的 Dion 产品规则，不能冒充已完整核验的 TC 行为：删除最后记录后自动删除备注文件、接受末条无终止换行、4096 字节包含行终止符、未知反斜杠组合按字面保留，以及具体名称匹配策略。用户期望自动删除与 TC 默认一致，但当前未取得该默认行为的明确官方保证。
